# Phase flow

## Execution

- Install/configure project-local; work within the launch dir + children; every file there = yours to edit.
- Long horizon → orient, then execute: one session carries a phase end to end across compactions, checkpointed on disk (`Session flow`).

## Session flow

- Phases, `Phase:` in `.agent/spec.md` = the phase + its scope (the whole product, or one surface or feature beside shipped parts that keep their own gates): PROTOTYPE → ITERATE → IMPLEMENT → MAINTAIN, a scope entering at the phase its request fits, backward included (`Routing`). PROTOTYPE, ITERATE, IMPLEMENT + every MAINTAIN request = one session each, body pasted by me: orient, then execute until the body's `Met when` holds.
- `.agent/spec.md` = the sole attached state, imported by the `@.agent/spec.md` line at the top of this file ⇒ MAIN + every teammate hold it from session start. Every line binds current or future work: superseded text dies in the commit that supersedes it, each unit prunes what its own close made dead, finished work → `.agent/archive/`; size is emergent. Five sections: `Intent` (human-facing, outranks the rest), `Artifacts` (path each, + run command where it runs), `Decisions` (rulings that bind), `Tasks` (the phase checklist: `- [ ]` open units in order, `- [x] <sha>` once committed, on-path finds appended, ticked rows cleared at each phase close + each MAINTAIN request's close; last line = pointer to `.agent/deferred.md`), `Phase` (state alone; its history → `.agent/archive/`); detail → `docs/` or `.agent/archive/`, deferral queue → `.agent/deferred.md` (one entry + acceptance check each). Shape check = `.agent/spec-lint`, a byte copy of `~/.local/app/agents/claude/spec-lint`: in the gate command from IMPLEMENT on, run at each PROTOTYPE + ITERATE close. Imports resolve at session start ⇒ a mid-session edit reaches a running teammate through its brief.
- PROTOTYPE = the fastest path to an artifact I can inspect, chosen for inspectability over production shape — a UI for a headless service, the CLI itself for a CLI tool, the figures for an analysis. Self-contained, disposable stack picked for speed, shortcuts + stubs welcome; it lives where `Artifacts` records it — `prototype/<name>/` by default, an isolated path in a shipped repo (shipped code it touches keeps its own gates). A prototype runs under PROTOTYPE law; verification integrity (global `Engineering`) binds the implementation. ITERATE opens by running the prototype artifacts (a surface without a live prototype first gets one: a copy of its shipped code, else its retired prototype from the `prototype-<scope>` tag), then works my feedback into them + `Decisions` in rounds until my go. PROTOTYPE + ITERATE = the quick loop that lets me grasp + decide business logic + direction: my rulings land in `Decisions`, each readable without the prototype; the prototype = their illustration.
- IMPLEMENT = the best version of the intended software, built greenfield from the locked direction (`Intent` + `Decisions`) under full global `Engineering` law, in whatever time that takes — gates, contracts + tiers, security scanning + update automation in gate + CI, adversarial review ledgered in `.agent/review.md`. A new repo starts from fresh code on a stack chosen anew, best in class (the prototype's competes like any other), gates + CI from its first commit; a shipped repo extends its codebase and keeps + extends what it already runs. Prototype code enters only re-implemented under these gates; a disposable prototype retires at close. MAINTAIN = one session per request — a feature, queued rows, a security review, a dependency upgrade — each closing gate-green with `spec.md` current.
- Routing: phase per kind of work — an open direction or nothing inspectable yet (new product or surface, rework of the whole or of a scope) = PROTOTYPE; rounds of my feedback on what I see (UI, UX, outputs) = ITERATE; a build past one session (new subsystem, redesign, large feature) = IMPLEMENT; a one-session request = MAINTAIN. A request needing a session or more of another phase → `~/.local/app/agents/claude/prompts/auto/route.md` (sets that phase up, ends the session); smaller work = a unit here, under the law of the code it touches; a same-phase scope joins the session's, recorded as a routed one. A PROTOTYPE, ITERATE or IMPLEMENT body I paste while `Phase` names another phase = a confirmed route: the routed state, then the body.
- Routed state: `Phase` line 1 = `<PHASE> — <scope>`; below it my request verbatim, `>` on every line (rank: above the body, below `Intent`; a later request of mine that conflicts → ask); then one `Suspended: <PHASE> — <scope>` line per scope left with open `Tasks` rows, those rows intact (its resume note → its in-flight row). A suspended scope rejoins once the flow reaches its phase (one spine, amended by the detour's outcome); a close into MAINTAIN resumes the latest one at its phase instead.
- This file = defaults; `.claude/rules/` = the repo's rulings on them. A rule keyed on the clause it overrides adapts, retires or marks inapplicable a structure named here (prototype location, CI, review ledger, spec layout) and names its replacement or my waiver; every phase body follows it, and a retired structure stays retired.
- Rules upkeep rides the `Tasks` clearing: each phase close + each MAINTAIN request close re-reads every `.claude/rules/` file in its context against global `Authoring` — dead law out, area-bound law → `paths:`, origin stories out (git keeps them).
- Checkpointing: a phase session compacts many times ⇒ state lives on disk — one commit per cohesive piece, `spec.md` current (`Tasks` ticked) at every commit, the working tree readable as a resume point. Gauge yourself (`context-gauge`; `context-alert` notices), land the current unit on a commit ahead of compaction, then continue; after compaction or resume, `spec.md` + `git log` = orientation.
- Teammates: fits, their reasons + mechanics = global `CLAUDE.md` `Subagents`; the phase sets teammate cost; the dispatch bar = the phase's in PROTOTYPE + ITERATE, each unit's depth in IMPLEMENT + MAINTAIN. Closing-diff `reviewer` → one per lens in IMPLEMENT (each lens its full attention), one covering every lens elsewhere.
  - PROTOTYPE + ITERATE: teammates = cheap + shallow, artifacts disposable ⇒ lowest dispatch bar: every separable piece larger than its brief = a fit (payoff = MAIN's freed time); parallel runs, small briefs, MAIN = orchestrator. Phase fits: `general-purpose` builds (artifact, component, spike, round change); `researcher` per design-reference sweep; `operator` visual QA of each artifact + finalist; variant fan-out where a choice is open (separate contexts keep premises distinct). Check-graded (approach, parameter) → one check fixed before the first variant (run command, metric) grades every variant; MAIN merges the winner. Taste-graded (UI design, UX, aesthetics, output form) → variety = the goal: a distinct premise per variant, ≥1 deliberately unconventional; MAIN keeps a spread of finalists, each its own `Artifacts` entry + screenshot, for me to compare, pick or combine at PROTOTYPE close + each ITERATE round; my pick retires the rest.
  - IMPLEMENT + MAINTAIN: teammates = deep; each unit's depth assessed with its tier. Deep = a `kernel` unit or one whose defect would reach me unseen ⇒ correctness, soundness + quality outrank teammate cost: dispatch wherever a teammate adds assurance MAIN's own pass would miss, a close call → dispatch; `consultant` on its contract before code (a contract error propagates into code + tests). Shallow = the rest ⇒ MAIN works alone + reviews each unit itself; teammates where work outruns MAIN alone (e.g. context overflow, a problem past its second failed attempt). MAINTAIN's closing-diff `reviewer` = where needed.
  - IMPLEMENT phase fits, any depth: `researcher` = SOTA survey on an open tooling, method, algorithm or analysis-design choice before the unit that commits to it, incl. a method PROTOTYPE picked for speed; `reviewer` per `data` unit; `operator` visual QA of each UI unit against `Decisions`.
- Advisor (use = global `Subagents`; its bar follows the dispatch bar): deep work = low bar: every global fit, each unit's contract before code + its files before commit; shallow work past ITERATE = high bar: an outcome MAIN's own judgment leaves open; PROTOTYPE + ITERATE = the global bar. Tool absent where a call would pay → ask me to send `/advisor claude-fable-5-1`; at orientation where the plan holds deep work.
