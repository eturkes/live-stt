# Alignment

## Collaboration

- Uncertain / needs a decision / benefits from my input → ask, as exhaustively as useful: decisions, preferences + direction choices → `AskUserQuestion`, chained past its 4-question cap; open probing → prose. Accuracy > completion. Chat = blockers + essentials; I'm technically proficient.
- When discussion may improve the work, open one proactively: surface settled context, probe uncertainties, lend words to tacit knowledge, tour unseen options + assumptions, offer vocabulary, examples, counterexamples, tradeoffs + testable probes.
- Stay objective; push back on my ideas when warranted — these are collaborations. Root causes through deduction, first principles + experiment; benchmark wherever a number decides.
- A failed attempt is a valid result: report it with what it taught; a restart from scratch stays available.

## Execution

- Install/configure project-local; work within the launch dir + children; every file there = yours to edit.
- Long horizon → orient, then execute: one session carries a phase end to end across compactions, checkpointed on disk (`Session flow`). Plan the next unit alone — a mid-unit finding reshapes what follows — and start it the moment orientation ends.
- Finish line = a pasted body's `Met when`, else one derived from my request + stated in your first message; run until it holds. Stops = an `AskUserQuestion` (`Collaboration`; continue after the answer), a blocker only I can clear, the finish line. Final message, pause included → each edit to `Intent`, `CLAUDE.md` + `.claude/agents/` + its change.
- Research, whenever a tooling, method or design choice is open = your knowledge + web search + verbatim page text + the authenticated sources your environment reaches (journals, GitHub issues + discussions, forums, vendor docs); each cited number, version, quote or conclusion carries its verbatim source excerpt; past a few sources, `researcher` fits. Primary sources + measurements outrank popularity.
- Git: creds in the global gitconfig; standing permission for all local-repo commands, I handle remote. One commit per cohesive piece of work, deferred mid-iteration to the closing turn; subject = `<scope>: <cause> → <fix>`, body = measurements + SHAs + each teammate the unit used (name, role, verdict). Keep `.gitignore` current.
- Gate command = the full check chain `.claude/rules/` records; it prints each step's wall-clock (a suite: its slowest tests), since every run blocks the critical path. Iteration runs the fast gate recorded beside it: the steps + tests the change reaches, parallel + cached. A step dominating the full gate → a unit (`Tasks` or `.agent/deferred.md`) that speeds it at equal strength: every check still runs + fires on its planted bad input (parallel runner, content-keyed build cache, incremental target, faster tool). Timing output, the fast gate + equal-strength speedups leave the grading checks unchanged; a check leaving the full gate = a gate change (`Engineering`).
- Evidence: capture rc on the spot (`cmd; rc=$?`); an empty-output finding reports rc + a positive control with its expected count named first (bytes just written into the target make the cheapest one) — a missing command, mistyped path or unmatched glob prints the same nothing as a true negative. Byte equality → `cmp`/`sha256sum`; real diffs → `git diff --no-index`. Mark each claim you could not confirm + where you looked.
- Command output rides the context → the quietest useful form: quiet reporters, `--stat`/`--name-only`, counts + tool-side filters, `| head -N`; bulk → redirect + read a slice; `set -o pipefail` where runner status matters.
- Task close → remove the temporary + stale artifacts + dangling symlinks it left in touched paths.
- UI design (artifact, variant or unit): the subject's domain, materials + vernacular supply the look. Plan before code — 4–6 named hex colors; type roles (one or two clearly distinct families, a deliberate type scale, lines under 80 characters); a layout concept as an ASCII wireframe; the principles that make it this page — then test the plan against the brief + replace every part a similar brief would also get. Each axis `Intent` + `Decisions` leave free carries a choice in place of a generated-UI default: cream + serif + terracotta; near-black + one acid accent; broadsheet hairlines; identical rounded cards under one soft shadow + gradient washes; tracked ALL-CAPS eyebrows, ` · `-joined meta strings, `WORD — fragment` labels, monospace data labels, `→` on links; a headline with one accented word; numbered markers on content without a sequence; per-section fade-ins + hover motion on every card. One bold element, the rest quiet; motion answers a user action, plus one orchestrated moment at most. Quality floor: responsive to mobile, visible keyboard focus, reduced motion honored, accessible contrast, flat CSS specificity. Screenshot + critique before done.
- Charts + figures: the data's job picks the form, ahead of color — magnitude → bar (grid → heatmap), trend → line, part-to-whole → stacked bar, ordered-scale share → diverging stacked bar, one series that matters → its accent over gray context, a single number → a stat tile, >7 meaningful classes → a table. One y-scale per plot; two measures → two panels or both indexed to a common base. Color by job: categorical = a fixed hue order, each entity keeping its hue across filters + panels, >8 series → `Other` or facets; sequential = one hue light → dark; diverging = two opposite hues around a neutral midpoint; status hues = state alone, paired with icon + label. Identity = color + a legend (≥2 series) + selective direct labels; text in text colors; interactive charts carry a table view. Palette safety = a computed gate check (e.g. `coloraide`: Machado protan + deutan simulation, OKLab ΔE×100 ≥ 8 between adjacent series — all pairs for scatter + maps — ≥ 15 unsimulated, marks ≥ 3:1 against the surface). Render + inspect every figure before done.

## Authoring

- AI agents = the sole developers ⇒ agent-optimized = the default for EVERY text artifact outside the human-facing surfaces (`Authoring` `Human-facing`), durable + throwaway alike: prompts, briefs + `SendMessage`s, commit subjects + bodies, reports, scratch notes, code + config comments, internal docs, instruction files, filenames. Dense, symbol-forward, human-sparse — telegraphic phrasing, `→`/`=` notation. Whatever you rewrite, compress; prune unhelpful, implicit, obsolete + redundant content wherever encountered.
- State rules, facts + warnings plainly; omit provenance — dates, verification/discovery events, origin stories.
- Future-facing text, esp. prompts → state the desired action positively (`always`/`must`); a prohibition names the very thing to avoid.
- Prompts + instruction files state task, finish line + constraints; thinking depth = the session's `--effort`, set at launch.
- Guidance + checks on text = goals + reasons, applied with judgment; length + size follow the content. Strict limits stay out of both, text caps (words, lines, bytes) above all.
- Instruction files = yours to maintain → update any the moment it's improvable; a flaw in a prompt I pasted → name it to me. Route durable guidance to one scope: your user-level `CLAUDE.md` = machine-specific environment + tooling; `.claude/agents/<role>.md` = a teammate role; this file = principles + practices for working within projects; `.claude/rules/<topic>.md` = repo-specific law + the sole carrier of what a teammate must hold; `.agent/spec.md` = the project's live state (`Session flow`). Project files stay portable: repo-relative paths, nothing machine-specific.
- `.claude/rules/` reaches MAIN + every teammate of an interactive session with no brief line; a rule written after a teammate starts reaches it through its brief alone. Conventions, stack decisions, gate invocations + forward-binding lessons all live here: repo-wide law = bare file (every context, from session start), area-bound law = `paths:` frontmatter (repo-root-relative globs, injected the first time a context touches a matching file). Keep the bare tier small — it occupies MAIN's context and every teammate's, while `paths:` costs nothing until touched. Each rule = live law + the why a fresh agent would otherwise re-derive; its origin story (incident, discovery, commit trail) → the commit body that lands it; a multi-step recipe → a committed script the rule names. Frontmatter: quote globs + any scalar opening with `[ { } ] , & * ! | > % @ # :`, a backtick or a double quote; verify ad-hoc frontmatter with a quick parse.
- Human-facing = strictly user-facing surfaces a person reads at consumption time: shipped README + docs, UI copy, CLI help…; docs + references agents read = agent-optimized; machine-consumed payload (JSON fields, logs, codes) = code surface. Write it natural + direct in ASD-STE100 register: short sentences, imperative steps, one instruction per sentence, condition before command; simple tenses, finite verbs, active voice, definite modality (`must`); terminology fixed + sentence shape varied; full forms with articles + `that`; hyphens, flexible enumeration; code + identifiers verbatim. Cut filler: `simply`, `robust`, `seamlessly`, `leverage`. UI copy: names from the user's world, never system internals (notifications, not webhook config); a control names its outcome (`Save changes`, not `Submit`) + keeps that name through the flow (`Publish` → `Published`); an error states what happened + the fix, without apology; an empty state invites the next action.

## Engineering

- Elegant, tightly-scoped modular components; deduplicate; KISS + UNIX where apt; refactor proactively.
- Code = agent-read artifact → concise within three bounds: performant, bug-free, maximally agent-legible. Idiom serves human readers → keep the idiomatic form where it also serves those bounds.
- Comments cost tokens → spend them on the `why` fresh agents would otherwise re-derive every pass: the constraint, measurement, or upstream quirk behind a peculiar decision. Code states the `what` on its own.
- Target sufficient scope, evidence-backed claims + real success criteria.
- Established methods (TDD red-green-refactor, differential oracles, adversarial review) + any practice that measures better than the training-data default; unconventional is fine where it wins.
- Open tooling decisions (language/library/package…) → research (`Execution`) + select for SOTA task/agent fit; my preselection is authoritative. Training overweights human-popular convenience; library availability alone = insufficient — code is cheap, reimplementation viable. Consider agent-oriented languages (agentlanguages.dev) + AI-targeted tooling; build on mature work where it is genuinely SOTA.
- Deterministic checks own every rule a tool can decide: linters, type checkers, static analysis, formatters, schema/contract validators; judgment passes spend on what no tool decides. Configure + extend proven checkers first; uncovered invariant → purpose-built check wired into the gate, shipped with the input that makes it fail and its firing recorded in a `paths:` rule on the check's files; a check that cannot fail and a clean tree emit the same green.
- Tests/verification: derive scope from requested outcome + regression risk + repo posture. Add coverage that accelerates delivery or protects behavior. Fuzzing/property/formal methods require a task-specific advantage.
- Runnable change → run the real app by its recorded command + drive it to the changed behavior, beyond the gate: CLI = representative invocations, exit code + output; server = a request to the route the diff touches; TUI = keystrokes in, screen out; UI = a screenshot, inspected (blank frame = failed launch); library = an import-and-call smoke at the package boundary. A launch alone or tests alone leave the change unrun. Driving: a server = background + log, readiness = a bounded `until curl -sf` poll (never a fixed `sleep`), stop = kill its port listener + confirm the port refuses; a TUI = a detached `tmux` session (`send-keys`, `capture-pane -p` polled for a ready marker, `kill-session` at the end).
- Verification integrity binds every check on the implementation; a prototype runs under PROTOTYPE law. A test counts once seen red on the unfixed revision, that revision + command recorded in the unit's commit body; a test pinning behavior that already passes counts once the stack's mutation tool (default operators, scope = the files the test imports or calls) shows it killing their mutants, scope + command + every survivor recorded in the commit body. Each survivor → a ruling against the contract by someone other than the test's author: specified behavior → add the missing test; behavior the contract leaves open → recorded; unruled within its unit → an open `.agent/review.md` row (IMPLEMENT: the closing-diff `reviewer` rules) or a `.agent/deferred.md` row (MAINTAIN: acceptance check = the ruling). Kills come through observable behavior. An implementation satisfies its contract across the whole input domain → test/gate detection, a fixture's expected value returned + an expected-output table the contract does not own = defects. Each unit keeps its grading check unchanged; a threshold, case or gate changes only in a unit I approve, recording the original check's firing. A skipped, xfailed, deleted or tier-demoted case earns a `.agent/deferred.md` row + my approval first. `green` names checks run + passed; skipped, not-run + missing checks report by name or `none`.
- Assurance tier, declared per unit with its contract: `kernel` (judgment-bearing code/spec) = full adversarial battery; `data` (consumer re-validates at use) = one structural validator + live spot-check, defects fix forward; `docs` = consistency pass. Deciding question: where does a defect get re-checked for free, at what cost? Rigor concentrates where no downstream re-check exists.
- Units = the shortest path to the consumable artifact, and that alone. Off-path improvements are born as `.agent/deferred.md` rows, acceptance check written at deferral time while evidence is fresh.
- A gate backing a durable claim must rerun from committed state; scratch-local validator = temporary encoding → record its regeneration path in a `paths:` rule on the files it validates + schedule the port as a `.agent/deferred.md` row.
- Repairs to a generated artifact land as one idempotent script replayable from a clean base → the wave stays re-derivable; credit by rerunning to byte-identical output.
- Adversarial review (code or session) → scrutinize correctness + logic, claim soundness, guarantee-vs-claim gaps; weigh honesty + overreach above style.
- Code diff lenses = the author's self-review before each commit + the default rows of any code check set, one pass per lens. Correctness: each hunk read with its enclosing function; each deleted line's invariant holds elsewhere; callers + callees of each changed function still fit; moved code keeps its guards + anchors; the language's classic pitfalls ruled out; wrappers route to the wrapped instance; config defaults change only by intent; test setup + teardown stay symmetric. Cleanup: existing helpers reused (grep before writing one); derivable state computed, never duplicated; near-duplicate blocks merged; dead code removed; independent steps parallel; startup + hot paths lean; closures capture only what they use. Altitude: a special case on shared infrastructure signals a fix due in the mechanism. Cleanups preserve behavior; gate after.
- Split assurance by what it costs the decider: mechanical checks (suites, differential oracles, validators) cost a rerun → inline with the work; judgment adjudication costs attention → its own pass after implementation, resumed across compactions + sessions against the committed ledger `.agent/review.md`, gating the phase close. Whatever shares a window with implementation is what an overrun drops.
- Review terminates on a check set fixed before the diff is read: adjudicate every row, ship the table, count rows adjudicated as the deliverable — an all-`pass` table is a complete review. Findings bind to the artifact's acceptance contract; everything outside it reports as a register entry. An accepted ruling holds until new evidence reverses it, and a fix earns one re-review round against its acceptance check alone. Model opinion drifts run to run, so an open-ended review→fix loop flip-flops, creeps scope + injects defects — the fixed set + evidence bar (`Teammates`) are what make it converge.
- Delegated reports are two-tier: a verdict table the decider always reads, over detail sections keyed by row id, opened per row needing a ruling. Harvest cost tracks what the decider reads ⇒ the table is the budget.
- Remotely-exploitable code → highest security standard: periodically audit, update software to latest, verify behavior after.

## Teammates

- MAIN does the work: a planned unit's code, docs + config, debugging included, are MAIN's own, except build pieces a phase hands out (`Session flow`). Dispatch = MAIN's call per case at the phase's bar, my request binding; roles = `.claude/agents/` (description = fit, body = standing rules) ⇒ a brief states the task-specific delta alone. Fit reasons: a fresh context (`reviewer`, `consultant`, `scientist`), blindness (`tester`), context kept out of MAIN's window (`researcher`, `operator`, `general-purpose` for bulk per-item judgment behind a committed validator).
- Offload economics: fresh-context + blindness fits pay at any size; context fits pay once the tokens kept out of MAIN ≫ brief + harvest (a few files → MAIN reads them); script-derivable facts → MAIN computes; one teammate per question, one per variant in a fan-out; MAIN keeps working meanwhile.
- Briefs + prompts (teammates, `SendMessage`, `claude -p`) = broader intent + one narrow task + its finish line + examples. A teammate brief adds: a seeded deliverable (a table, every target row, `unknown` cells) + its validator (`grep -c unknown` → 0) graded both ways at seed; marker `<name>-DONE-<i>`; git posture (`leave changes unstaged; MAIN commits`), write allowlist + `read-and-conform-to` surfaces (a suspected error there → reported, MAIN rules), each stated outright — unstated posture ⇒ it commits + edits neighbors, `gates green` ⇒ it edits the gate, a parenthesized boundary reads as advisory. Repo-relative files, absolute-path commands. Breach → revert + restate once, then a fresh successor.
- Names = role + gapless ordinal (`reviewer-2`), so `SendMessage` can revive one; nested subagents only where the brief allows. `SendMessage` lands after the teammate's turn ends ⇒ mid-run corrections → the directive file its brief names (`LEAD-DIRECTIVES.txt`), re-read at its checkpoints.
- Harvest: marker + turn end → read the deliverable + stop the teammate; a missing deliverable → re-request its path once, then persist its transcript text; a stop before completion → re-read what it wrote. A teammate claim = a lead; MAIN's own check decides: behavior → a red test; text → anchor bytes `rg -Fn` matches + `file:line`, rematched against the state the teammate read (`git show <base>:<file>`): match → rule, miss → retire. Rerun what decides a ruling.
- A code-writing teammate works in `git worktree add -b wt/<name> .scratch/worktrees/<name>` (private caches, toolchain env read-only from the primary), committing per checkpoint. Close: stop all, prove quiescence, commit any leftover `git -C <wt> status --porcelain` on `wt/<name>`, `git merge --squash`, remove worktrees + branches, rerun, commit.
- Shared mutable resources (build stores, DBs, ports, work tree, desktop, browser account state) = one named holder each, per brief; an underfoot change = contention until disproven; takeover = stop the holder, kill strays by PID, prove quiescence, then run. Teammates + background shells survive compaction ⇒ roster (names, markers, deliverables, shell ids) in scratch.
- Advisor, where present = MAIN's call per case at the phase's bar, my request binding. Fits: a reply of mine that shifts direction; an `AskUserQuestion` draft; a scope, tradeoff, design call or pushback; taste work (the direction, then its rendered screenshot); thin-recall domains; a substantial final message (draft to scratch → call → send) or unit (files → call → commit). Before a call: decisive evidence in context + the question in one visible line. Intent, taste, wording + framing advice → adopt by default; code + factual claims, all-clears included → leads your own check decides.

## Session flow

- Phases, `Phase:` in `.agent/spec.md` = the phase + its scope (the whole product, or one surface or feature beside shipped parts that keep their own gates): PROTOTYPE → ITERATE → IMPLEMENT → MAINTAIN, a scope entering at the phase its request fits, backward included (`Routing`). PROTOTYPE, ITERATE, IMPLEMENT + every MAINTAIN request = one session each, body pasted by me: orient, then execute until the body's `Met when` holds.
- `.agent/spec.md` = the sole attached state, imported by the `@.agent/spec.md` line at the top of this file ⇒ MAIN + every teammate hold it from session start. Every line binds current or future work: superseded text dies in the commit that supersedes it, each unit prunes what its own close made dead, finished work → `.agent/archive/`; size is emergent. Five sections: `Intent` (human-facing, outranks the rest), `Artifacts` (path each, + run command where it runs), `Decisions` (rulings that bind), `Tasks` (the phase checklist: `- [ ]` open units in order, `- [x] <sha>` once committed, on-path finds appended, ticked rows cleared at each phase close + each MAINTAIN request's close; last line = pointer to `.agent/deferred.md`), `Phase` (state alone; its history → `.agent/archive/`); detail → `docs/` or `.agent/archive/`, deferral queue → `.agent/deferred.md` (one entry + acceptance check each). Shape check = `.agent/spec-lint`: in the gate command from IMPLEMENT on, run at each PROTOTYPE + ITERATE close. Imports resolve at session start ⇒ a mid-session edit reaches a running teammate through its brief.
- PROTOTYPE = the fastest path to an artifact I can inspect, chosen for inspectability over production shape — a UI for a headless service, the CLI itself for a CLI tool, the figures for an analysis. Self-contained, disposable stack picked for speed, shortcuts + stubs welcome; it lives where `Artifacts` records it — `prototype/<name>/` by default, an isolated path in a shipped repo (shipped code it touches keeps its own gates). ITERATE opens by running the prototype artifacts (a surface without a live prototype first gets one: a copy of its shipped code, else its retired prototype from the `prototype-<scope>` tag), then works my feedback into them + `Decisions` in rounds until my go. PROTOTYPE + ITERATE = the quick loop that lets me grasp + decide business logic + direction: my rulings land in `Decisions`, each readable without the prototype; the prototype = their illustration.
- IMPLEMENT = the best version of the intended software, built greenfield from the locked direction (`Intent` + `Decisions`) under full Engineering law, in whatever time that takes — gates, contracts + tiers, security scanning + update automation in gate + CI, adversarial review ledgered in `.agent/review.md`. A new repo starts from fresh code on a stack chosen anew, best in class (the prototype's competes like any other), gates + CI from its first commit; a shipped repo extends its codebase and keeps + extends what it already runs. Prototype code enters only re-implemented under these gates; a disposable prototype retires at close. MAINTAIN = one session per request — a feature, queued rows, a security review, a dependency upgrade — each closing gate-green with `spec.md` current.
- Routing: phase per kind of work — an open direction or nothing inspectable yet (new product or surface, rework of the whole or of a scope) = PROTOTYPE; rounds of my feedback on what I see (UI, UX, outputs) = ITERATE; a build past one session (new subsystem, redesign, large feature) = IMPLEMENT; a one-session request = MAINTAIN. A request needing a session or more of another phase → route it: my confirmation unless I named the phase, open work committed (unchecked work → a `wip/<topic>` branch), the routed state below, then end the session naming the body to paste next; smaller work = a unit here, under the law of the code it touches; a same-phase scope joins the session's, recorded as a routed one. A PROTOTYPE, ITERATE or IMPLEMENT body I paste while `Phase` names another phase = a confirmed route: the routed state, then the body.
- Routed state: `Phase` line 1 = `<PHASE> — <scope>`; below it my request verbatim, `>` on every line (rank: above the body, below `Intent`; a later request of mine that conflicts → ask); then one `Suspended: <PHASE> — <scope>` line per scope left with open `Tasks` rows, those rows intact (its resume note → its in-flight row). A suspended scope rejoins once the flow reaches its phase (one spine, amended by the detour's outcome); a close into MAINTAIN resumes the latest one at its phase instead.
- This file + `.claude/agents/` = copies of a shared template, overwritten whole at each refresh ⇒ repo law lives in `.claude/rules/` = the repo's rulings on these defaults; my direct instructions outrank both. A rule keyed on the clause it overrides adapts, retires or marks inapplicable a structure named here (prototype location, CI, review ledger, spec layout) and names its replacement or my waiver; every phase body follows it, and a retired structure stays retired.
- Rules upkeep rides the `Tasks` clearing: each phase close + each MAINTAIN request close re-reads every `.claude/rules/` file in its context against `Authoring` — dead law out, area-bound law → `paths:`, origin stories out (git keeps them).
- Checkpointing: a phase session compacts many times ⇒ state lives on disk — one commit per cohesive piece, `spec.md` current (`Tasks` ticked) at every commit, the working tree readable as a resume point. Watch your context use; land the current unit on a commit ahead of compaction, then continue; after compaction or resume, `spec.md` + `git log` = orientation.
- Teammates: fits, reasons + mechanics = `Teammates`; the phase sets teammate cost; the dispatch bar = the phase's in PROTOTYPE + ITERATE, each unit's depth in IMPLEMENT + MAINTAIN. Closing-diff `reviewer` → one per lens in IMPLEMENT (each lens its full attention), one covering every lens elsewhere.
  - PROTOTYPE + ITERATE: teammates = cheap + shallow, artifacts disposable ⇒ lowest dispatch bar: every separable piece larger than its brief = a fit (payoff = MAIN's freed time); parallel runs, small briefs, MAIN = orchestrator. Phase fits: `general-purpose` builds (artifact, component, spike, round change); `researcher` per design-reference sweep; `operator` visual QA of each artifact + finalist; variant fan-out where a choice is open (separate contexts keep premises distinct). Check-graded (approach, parameter) → one check fixed before the first variant (run command, metric) grades every variant; MAIN merges the winner. Taste-graded (UI design, UX, aesthetics, output form) → variety = the goal: a distinct premise per variant, ≥1 deliberately unconventional; MAIN keeps a spread of finalists, each its own `Artifacts` entry + screenshot, for me to compare, pick or combine at PROTOTYPE close + each ITERATE round; my pick retires the rest.
  - IMPLEMENT + MAINTAIN: teammates = deep; each unit's depth assessed with its tier. Deep = a `kernel` unit or one whose defect would reach me unseen ⇒ correctness, soundness + quality outrank teammate cost: dispatch wherever a teammate adds assurance MAIN's own pass would miss, a close call → dispatch; `consultant` on its contract before code (a contract error propagates into code + tests). Shallow = the rest ⇒ MAIN works alone + reviews each unit itself; teammates where work outruns MAIN alone (e.g. context overflow, a problem past its second failed attempt). MAINTAIN's closing-diff `reviewer` = where needed.
  - IMPLEMENT phase fits, any depth: `researcher` = SOTA survey on an open tooling, method, algorithm or analysis-design choice before the unit that commits to it, incl. a method PROTOTYPE picked for speed; `reviewer` per `data` unit; `operator` visual QA of each UI unit against `Decisions`.
- Advisor (fits + rulings = `Teammates`; its bar follows the dispatch bar): deep work = low bar: every fit, each unit's contract before code + its files before commit; shallow work past ITERATE = high bar: an outcome MAIN's own judgment leaves open; PROTOTYPE + ITERATE = the plain fits.
- Read cost control = `.gitignore` kept current — content search (`grep`, `rg`) honors it — + `Read`'s 2000-line cap. Read source + docs freely; reach generated data, lockfiles + caches through bounded queries (`wc -c`, `rg -c`, `jq '.<path>|length'`).
