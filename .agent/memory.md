## Orientation

**What it is:** real-time Japanese STT + English translation, fully local STT, no API keys (D-009). Pipeline (`live_stt.py` ~1,470 lines + `streaming.py`, D-002): mic → `resample` → 2 s `AudioQueue` → silero VAD → **VAC controller** (speech-start opens a LocalAgreement-2 buffer in `streaming.py`; every `VAC_CHUNK_S` re-decodes the open buffer and commits what two decodes agree on; speech-end flushes the tail unconfirmed) → **whisper large-v3-turbo int8 on OpenVINO NPU** (D-016) → `CodexTranslator` (JA→EN over a persistent `codex app-server`, JSON-RPC/stdio, D-011) → `emit_line` → stdout + the per-session `transcripts/` file (saved by default). Partial text renders on the meter status line; one utterance = one numbered `JA` line = one translation turn. `--engine k2v2|parakeet` selects the **sherpa fallback path** (VAD-segment close → ring pre-pad re-slice → 8-segment queue → sequential low-RMS chunked decode, D-010); `--asr-device` selects the OpenVINO device for the default engine. Degrades to JA-only when codex is absent/failing (hard requirement, D-009).

**Gate identity = `gate.py`, executable, not prose.** `uv run --no-sync python gate.py` owns the exact step set and file list; `tests/test_gate.py` locks the inventory and proves each blocking step can fail the runner (one seeded defect per step, in a throwaway tree). Do not re-specify steps here — read the script. Six steps: pytest · ruff-check repo-wide · ruff-format on touched `*.py` · pyright over `live_stt.py replay.py cer.py streaming.py` · pyright over `tests/` · offline `import live_stt`. Every step is fast and hermetic: no weights, no hardware, no network. `--only NAME` runs one step; `--files …` overrides the touched-file list. The script clears `PYTHONPATH` itself. **`ruff` is not on `PATH`** — the module form (`python -m ruff`) works from any environment that has it.

Format-step rationale, corrected by measurement: repo-wide `ruff format --check .` stays red on **ten** files, and that red is **wrapping drift, not protected hand-layout**. Every one of the 19 pre-existing hunks is ruff joining a wrapped expression under `line-length = 100`, plus two blank-line fixes; no comment content and no aligned table is at stake, so D-006/L-001 do not defend them. The step is per-touched-file so each unit leaves its own files clean and the repo converges; `live_stt.py` converged in M11.1 (`polish.md` P-003 holds the rest). Touched files = touched **Python** files: `ruff format` skips `.json`/`.md` when traversing a directory (`--check .` on a JSON-only tree reports "No Python files found", rc 0), but an explicitly-passed path with an unknown extension is parsed as Python — a literal `.json` arg exits 1 proposing Python-dict layout. Filter the step to `*.py`; there is nothing to add to `extend-exclude`.

**Known caveats:**
- Models are a runtime prerequisite — `check_models()` preflights and points at `models/README.md`.
- Silero opens segments 0.2–0.7 s late (D-010); every segment is re-sliced from the ring with `VAD_PRE_PAD_S=0.4` lead-in — VAD/worker edits must preserve this.
- Raw long segments (>~15–20 s pause-less) degrade both offline decoders via wholesale deletions; the shipped worker now protects >10 s segments with low-RMS overlapped chunking (L-023). Paused speech + short segments retain the original single-decode path.
- Tool-feature disables in `_CODEX_CONFIG` are THE latency lever (D-011): re-enabling web_search/browser/apps re-injects ~15 K tokens/turn (p50 0.99 s → 3.15 s) — keep them off.
- Codex auth is external state (`~/.codex/auth.json`, check existence only, never read); plan reports `pro`, Spark entitled regardless (D-011).
- `sherpa-onnx` + `sherpa-onnx-core` (carries libonnxruntime) are both pinned — keep both (uv once skipped the declared sub-dep).
- sherpa online gotcha: `from_transducer(enable_endpoint_detection=…)` surfaces as config `.enable_endpoint`; `OnlineRecognizer.reset(stream)` resets by side effect and returns `None` despite its bool annotation — never branch on the return.
- Benign default-engine STT quirks: ジェミニ→ゼミニ, 文→分 homophone — EN leg translates through them.
- The EN leg needs `codex` on the PATH of the machine *running* live-stt; installs/logins are per-machine, user-only, and a container login does not carry over. Both layers have it now — host installed + EN confirmed live there (second smoke, 2026-07-02).

## Decisions (D-002 … D-014)

ADR-style, compact — active decisions only. When one is superseded, delete it and fold any still-live constraint into the successor; the prior record lives in git + `roadmap.md`.

- **D-002 — Single-file `live_stt.py`.** No package/module split: one dev (agent), one user; splitting buys reuse/isolation we don't need and costs context per file. M9.5 revisited the ~1,000-line threshold: the feeder/decoder stages share config, state, replay hooks, and shutdown order, remain adjacent, and introduce no navigation incident → keep one file. Revisit on an actual navigation failure or a cohesive one-way subsystem boundary. **`streaming.py` is the one taken split** — the LocalAgreement-2 hypothesis buffer is exactly the sanctioned "cohesive one-way subsystem": pure text-in/text-out, no app config/state/shutdown coupling, independently testable, so it qualifies under this clause rather than violating it. The rule is unchanged for everything else; a second split needs its own naming of the boundary.
- **D-004 — `.agent/` shape = the lean memory system.** Current shape: `memory.md` + `roadmap.md` + `polish.md`, all committed (a fresh clone reproduces durable context per `CLAUDE.md`'s long-horizon rule). Those three arrive attached and whole on every session, so they stay minimal. One sanctioned extension sits outside that attached set: `archive/<record>.md` = closed-milestone detail lifted out of the roadmap, reached through the roadmap summary's pointer. `polish.md` earns a file by lifecycle rather than topic: its rows are consumed and pruned by `/session-polish`, while memory's lines are durable and roadmap's track milestone state. The context gauge is no longer in tree: it is the machine-scoped `context-gauge` in `~/.local/bin`, project-independent and therefore owned by the global scope per `CLAUDE.md`'s routing rule. *Resist re-expanding into per-topic files — the single memory file is the decision, and `archive/` takes closed-milestone detail alone. The 2026-09-02 cut deleted `contracts/` and the review ledger; a unit's acceptance belongs in its roadmap entry and its outcome in the commit body (L-032).*
- **D-005 — Superseded-spike docs pruned; the live rationale is the decision log, not in-tree reports.** The Gemini (T3.1) + metered-backends spike reports and the rejected `codex_ws/AGENTS.md` prompt-mechanism were removed from tree at user direction (2026-07-20); git history preserves them. They justified abandoned cloud branches — the actual cloud→local trail is D-009/D-010/D-011 + the roadmap ledger. Do not re-add spike reports for superseded work; record the decision here instead.
- **D-006 — Don't refactor `live_stt.py` for "LLM-readability."** Its optimization comments encode irreplaceable rationale; denser naming saves ~30 tokens at every call-site's expense (L-001). Target a specific confusing line only on a real incident, never the whole file.
- **D-007 — Pre-commit hook via `.githooks/` + `core.hooksPath`, not the `pre-commit` framework.** The hook is one line (`uv run pytest -q`); the framework adds schema + per-hook venv cache + network bootstrap for nothing at this scope. Each clone opts in once (`git config --local core.hooksPath .githooks`). `--no-verify` bypasses for emergencies. Revisit if the hook grows past one or two commands.
- **D-008 — `.claude/settings.json` deny-list.** Denies the do-not-read set in § Orientation to keep secrets, bulk data, and regenerable state out of context. The rule applies at the Claude tool boundary; project scripts may construct and read those paths at runtime (L-016). Keep the list synchronized with `CLAUDE.md` and narrow a rule when a task legitimately needs a blocked path.
- **D-009 — No-API-key architecture: local STT + Codex-subscription translation, Gemini replaced outright.** Trigger: user wants a Codex subscription, no API keys. Supersedes the Gemini backend (T3.1/T3.2), kills T-BACKENDS-001. STT leg = local CPU-only streaming JA engine (D-010); translation leg = Codex subscription text surface via the sanctioned persistent CLI (D-011), chosen over the undocumented backend endpoint and over Codex `[realtime]` voice (agentic-loop-wrapped, 60 s-capped — unfit as a transcriber). Local MT rejected by user (wanted GPT-quality EN at zero marginal cost). ## Lessons (L-001 … L-032)

Generalizable rules from past mistakes/findings — active only. Tests cite L-004. Delete a lesson once obsolete or folded into another; git holds it.

- **L-031 — Size work by the decisions it forces, not by its line count.** Measured over six closed M11 units: Spearman **-0.395** between insertions and context cost (n=6, descriptive), and the extremes invert — the smallest unit by lines (254) was the only one to overrun a window, while the largest (1,725) was the cheapest. The real predictor is decisions originated inside the work: the cheap unit had its whole surface enumerated before it started, the expensive one hit two unmapped collisions at the gate. Rule: one independently closable deliverable at a time, and split when a piece would force more than a couple of its own design rulings. Never write a "close on partial acceptance if you run out of room" clause — it relabels a known overrun as a plan.
- **L-032 — Keep assurance proportional to the artifact; measure the ratio periodically.** This repo reached ~11,100 lines of verification apparatus around a 2,108-line personal tool: an AST-closure contract fingerprint whose only job was to REFUSE a cached rebuild, a 40-row claim registry validating citations for prose the same author wrote, mutation testing to prove the tests were not vacuous, and a model-tournament stack for a decision already made outside it. The tell was mechanical and visible three units before it was acted on: **the fingerprint needed a hand-written, individually-pinned migration clause in three consecutive units**, each one waving through a legitimate code change. A guard that must be escaped every time it fires is not a guard. Ask what re-checks a defect for free and at what cost (`CLAUDE.md` assurance tiers): for a single-user tool, a fast test suite, a replay golden answering "did the output change", and a scoring script run on demand cover it, while provenance machinery costs more than the defects it catches. The cut deleted 21,038 lines and took the suite from 466 tests / 48 s to 207 / 14.6 s with **zero production change**.
- **L-001 — Don't over-edit optimized code for "LLM-readability."** Keep comments that encode a non-obvious invariant/optimization and naming that's already domain-aligned; only edit when you can name a specific failure mode the edit prevents.
- **L-004 — Mic and real-terminal paths are agent-unverifiable.** The sandbox has no mic/interactive TTY. Any change touching `sd.InputStream`/`audio_callback`/real-time latency/Ctrl+C/multi-hour behavior gets a "**Did not verify**" list (see § Smoke) naming each path for the user; do not claim "done" without it.
- **L-005 — Avoid abstractions in `live_stt.py`.** Trajectory is consistently "less code wins"; default to inlining, no config/DI/plugins/class hierarchies unless the task requires them.
- **L-006 — TTY-gate the cursor-clear (`\r\x1b[2K`) protocol per stream, evaluated once.** stderr: the `logging.Formatter` prepends it gated on `sys.stderr.isatty()` so redirected logs are ANSI-free — the rare ~10-line subclass that beats inlining (vs L-005). stdout: the meter status line + `emit_line` gate on module-level `_STDOUT_TTY = sys.stdout.isatty()`, so redirected stdout stays ANSI-clean and the meter is silent off-TTY; any new stdout status writer gates the same way.
- **L-008 — A single user preference is state, not an "always" rule.** Record placement/config choices as *current state* with their decision source, not as `always`/`never` laws; ask before reversing a user-set arrangement. Reserve firm lessons for technically-derivable facts.
- **L-010 — Keep device-backend imports at device entry points; check a dlopen'd native lib by importing its binding.** PortAudio probes host audio controls during `sounddevice` import; eager app-module import can hang model-only evaluators on an unhealthy device. `run_session` + `--list-devices` own the imports; offline replay/test stays hardware-independent. This container's `ld.so.cache` is empty yet libs resolve fine; verify mic prerequisites with `uv run python -c "import sounddevice"` or `dpkg -l libportaudio2`, not `ldconfig -p`.

Use the existing manifests/tooling for deny-listed corpora rather than exposing bulk inputs directly.

Keep package versions out of memory (drift risk).

- **L-022 — Adversarial-review follow-through: fix with a non-vacuous lock, and record the rejects.** Codex Finding 1 (HIGH) surfaced an "enable-over-corpse" startup race (a warm-up/health check that completes just before an async child dies can flip you "live" over a finished reader). Durable pattern: **validate liveness at the commit point** (re-check `_reader_task.done()`/`returncode` immediately before `enabled=True`), not only at spawn. Two reusable test techniques: (a) **deterministic async-EOF** — buffer every response line AND `feed_eof()` in one synchronous burst before the read loop drains; `StreamReader.readline()` returns without yielding when a line is already buffered, so EOF is guaranteed processed before the code under test reads liveness. - **L-023 — Long continuous speech defeats soft caps and offline decoders; test with a genuinely-continuous stressor.** sherpa's silero `max_speech_duration` (default 20 s) raises the threshold (0.5→0.9, min_silence→0.1 s) instead of hard-cutting — dip-less speech grows unboundedly, so VAD tuning alone cannot bound segment length. Offline attention/transducer models delete content wholesale past ~15–20 s; segment LENGTH, not synthetic-vs-real audio, is the degradation axis (D-010's "TTS collapse" was this), engine-dependent — k2v2 collapses ~3–4× harder than parakeet before mitigation. Build a continuous stressor from real short clips via silero-trimmed speech extents + ~10 ms equal-power crossfade joins (gap-concat leaves clip-edge quiet the VAD rightly splits on); the trim costs onset deletions on isolated decode (silero opens late; 0.4 s pre-pad recovers) → record a per-component baseline and report EXCESS deletion (stressor D − Σ baseline D), else the stressor measures its own construction artifact. Measured construction/QC numbers + WAV sha256 live in `tests/stressor_clips.json`; current shipped-pipeline scores live in `tests/cer_baseline.json`. Prove the corpus honestly, not by loose proxy (`n_seg < n_comp` is gameable — passes at 14/15): continuity = every crossfade-join offset sits inside a cap-OFF VAD segment; soft-cap causality = cap-ON yields more segments than the cap-OFF control. Fix lesson (M9.4): lowering the soft cap 5–12 s still leaves 9–16 s blocks and adds harmful reset boundaries; retain 20 s endpointing, preserve ≤10 s input by identity, then split only longer decode slices into balanced ~2 s low-RMS views with small overlap + conservative exact text merge. Gate total CER alongside deletion so overlap duplication cannot game the deletion target. Genuine narration answers a different question: M9.6's 4:48 chapter naturally endpoints to a ≤9.686 s resliced upper bound, validating long-session completeness but not the >10 s split — keep the continuous stressor as the split-path gate. The committed pause-free gate is 44.7 s; do not claim arbitrary duration because one VAD segment surviving beyond `RING_SECONDS`=60 loses its unretained head. Gotcha: `max_speech_duration` × 16 kHz is an int32 sample count — a huge sentinel (≥~1e6 s) overflows → spurious splits; the control 'off' is a cap just above audio length (`make_vad(max_speech_s=120)`).

- **L-026 — A model bench is only evidence if the harness mirrors production failure handling and the judge sees raw candidates.** Import the real config/instructions/thread options rather than retyping them, and copy the production cleanup path: a `codex app-server` turn that times out keeps running server-side, so without `turn/interrupt` + note drain one stall silently converts every later turn into a timeout — a 5-turn "model failure" that is really one stall plus a harness defect. Present judge candidates between explicit `[Cn]`/`[/Cn]` markers, never through `repr()`/quotes: quoting every candidate makes each look like it added quotes and caps the format-contract score for the whole field at once. Interleave repetitions across configs (rep1 all configs, then rep2) so server-load drift hits every config alike, run configs sequentially so latency stays uncontended, and compare tiny quality gaps paired on the same (item, rep, judge) grading with a bootstrap CI — marginal means put a config "ahead" at differences a paired CI shows as zero.

- **L-027 — A deterministic content probe measures your regex until you read the misses.** Per-item `must`/`forbid` regexes catch real content loss cheaply and objectively, but nearly every early miss was the pattern, not the model: spelled-out numbers ("six units"), hyphens ("stage-two", "12-unit"), synonyms ("decreased" vs "reduced wall motion"), analyte variants ("PaCO2" vs "pCO2"), reversed negation order ("resuscitation will not be performed" against a pattern demanding `not` before `resuscitat`), and legitimate alternate renderings (the Japanese brand "Predonine"). Two habits make the layer trustworthy: (a) validate every pattern against an authored reference translation at corpus-build time and fail the build on mismatch — this catches inverted/typo'd patterns before any turn is spent; (b) treat each first-run miss as a suspect regex and read the actual output before recording it as a model error. Five loosening rounds took 702 turns from ~20 apparent content failures to 7 real ones. Keep every loosening synonym-only, so a wrong dose, side or negation still fails. Mirror trap, and the more dangerous one: a *passing* pattern can hide a real defect. `must.drug` = `prednis|predonine` passes for prednisolone AND prednisone — different molecules — so the declared probe and the aggregate quality scores both scored the wrong-drug turn as clean; only an explicit discriminating check found it. Once a defect is named, write a check that separates it from the correct output instead of reusing the declared pattern, and A/B against that check rather than against the aggregate. Corollary from the instruction probe: attribute a fix to the line that causes it — run one arm per candidate line cumulatively, since the drug-only arm showed the drug line does nothing for gender.
- **L-024 — Backpressure capacity is time; prove it with paced production replay.** Callback block sizes are backend-selected, so a block-count queue cannot express audio headroom; bound queued PCM seconds directly. Fast-as-possible file replay also cannot expose real-time serialization: pace production arrivals on a virtual sample clock, replace only decode cost, and retain the production worker/VAD/ring/queue/drop policy. Keep feeding separate from sequential decode, copy ring slices before queueing them, bound both stages, and failure-couple siblings; otherwise a slow decode either blocks VAD ingestion, lets later ring writes corrupt queued views, or strands a stage after its peer dies. Pair the deterministic stress with live meter/soak checks: modeled timing proves the known workload, not arbitrary host scheduling.

- **L-025 — Evaluator completeness is input/event accounting, not nonempty text.** On the complete short corpus, both offline controls consumed every sample + EOF exactly once yet shared 10 identical empty hypotheses with `segments=[]` (quiet/short material rejected by the common production VAD). These are completed ASR misses → retain the case IDs and score D=N. A failed/partial corpus run means missing/duplicate/reordered IDs, unconsumed audio, wrong EOF/finalization, or a worker exception; it never means one completed clip emitted no text. Keep “nonempty run” corpus-level, or a shared frontend can make every downstream candidate fail by construction. Backend-declared generation/context truncation is a third state: the input run completed, but the output is knowingly terminal-limited → capture native diagnostics per phase/case and fail a separate deterministic content gate instead of relabeling completion or silently scoring the warning away. Publish only exact indexed runs; detailed hashes + aggregate atomicity prevent partial evidence from masquerading as a model result.

- **L-028 — A parallel-corpus reference is a judge-validity probe, never a translation ceiling.** FLEURS EN and JA are independent renderings of a shared source, so neither is a translation of the other and the JA routinely carries specificity the EN drops (`胡氏` → "He"). Scored blind against the JA source, the human EN reached adequacy 4.255/5 while MT over the *perfect* JA transcript reached 4.880 — report that gap as a property of the corpus, never as "MT beats human." Two durable consequences. (a) The low human score is the payoff, not a defect: a judge that docks fluent, human-authored English for diverging from the source is demonstrably grading content rather than rewarding fluency, which is exactly the assurance an adequacy claim needs — so keep the reference in the blind field and read it as instrumentation. (b) String metrics against such a reference are bounded far below their nominal maximum for correct output (oracle chrF2++ 57.75), so use them to rank arms sharing one reference and never as an absolute quality level. Generalize: when a "gold" candidate scores near the system under test, suspect the gold's provenance before crediting the system.

- **L-029 — A seeded report skeleton only checkpoints work when each row is independently answerable.** Two teammates got the identical treatment — a committed skeleton, every cell `unknown`, "flush every 4 rows", and `grep -c unknown` polling. The surface-map agent delivered 17/17 and flushed steadily; the evidence-digest agent delivered 0/12 and ignored three escalating flush directives, ending at 72 % of its window with everything still in its transcript. The difference was row shape, not discipline: map rows were **lookups** (one named surface → its anchor, its test, its gap), each answerable the moment that file was read, so flushing cost nothing. The digest's rows were **synthesis** (build a claim→producer table across ~12 scripts and ~30 result files), where no single row is honestly fillable until nearly everything is read — so the agent rationally kept reading, and the checkpoint contract silently became all-or-nothing. Design consequence: when scoping a teammate, ask whether row *k* can be answered without row *k+1*. If not, restructure the deliverable into per-source rows ("what does `X.py` produce") and make the synthesis its own final row, so the expensive reading is banked as it happens. Recovery when it fails anyway: a live agent's transcript is readable (`context-gauge -p <name>` → `jq` the `tool_use` inputs), so mine it before `TaskStop` — the tool-call record showed which files were read and what was computed, and that salvaged the inventory that never reached disk.

## Smoke checklist — agent-covered vs user-only (L-004)

**Agent-covered (M9):** the two-engine replay/CER gates own short-transcript stability, genuinely-continuous >10 s decode behavior, and the full-file 4:48 narration path. Paced production replay owns the 44.722 s / 20 ms callback / decode-RTF 0.20 backpressure case (max audio queue 0.020/2.000 s, segment queue 1/8, `drop=0`) plus all 7 short clips. Pure tests own drain-on-shutdown, sentinel landing, stage-failure cancellation, and translator degradation. These gates exercise the real worker but not a microphone driver, OS signal timing, real Codex happy path, or elapsed multi-hour behavior.

**User-only boundary:** mic capture, device select, latency feel, real Ctrl+C flush, `-o` persistence, Codex cadence, and multi-hour soak. This is the fixed procedure a "Did not verify (L-004)" disclaimer points at; each item names the `live_stt.py` observable that decides pass/fail. **Setup:** models downloaded; `codex` installed on the `PATH` of the machine/environment running live-stt; `codex login` there once for the EN leg (without it: `Translation: unavailable — JA-only`, EN checks N/A). One utterance = speech + a ≥0.5 s pause (`VAD_MIN_SILENCE_S`).

**Live-mic pass (~5 min):**
1. **Devices** — `uv run live-stt --list-devices` lists the `sd.query_devices()` table and exits. Pass: your mic shows with input channels.
2. **Capture + backlog** — `uv run live-stt`, speak. Pass: `JA n:` lines print (capture + decode live); `q=` / `seg=` are absent or brief and clear after each utterance; any `drop=N` fails.
3. **Device select** — `uv run live-stt --device N`. Pass: prints `Mic: #N <name> @ <rate> Hz`; capture works as in (2).
4. **Latency + endpointing (VAC cadence, D-016 — NOT the old 0.6 s VAD-segment rule)** — one sentence, then stop. Pass: partial text grows on the meter status line *while you are still speaking* (first characters ~2.1–2.5 s in on measured audio, committed only where two consecutive decodes agree), then the numbered `JA n:` line lands after you stop; a brief mid-sentence pause does not split it. Committed characters must never be rewritten or duplicated once shown (`emitted` is append-only). On `--engine k2v2|parakeet` the old rule still applies: no partials, `JA n:` ~0.6 s after you stop (0.5 s `VAD_MIN_SILENCE_S` + ~0.1 s decode, D-010).
5. **Translation cadence** — Codex up. Pass: each `EN n:` trails its `JA n:` by ~1 s, shared `n` keeps pairs matched; `--no-translate` suppresses every EN line.
6. **Ctrl+C mid-utterance** — start speaking, Ctrl+C while still talking. Pass: the in-progress `JA n:` still prints (worker flushes the VAD in `finally`), its `EN n:` still lands if Codex is up (translator drains last), then `Stopped.` with no hang (non-blocking shutdown sentinel, T8.1).
7. **Ctrl+C mid-decode** — run `uv run live-stt --engine parakeet`, speak continuously for >20 s, pause, then press Ctrl+C immediately while the slower long-block decode is running. Pass: that block's `JA n:` still lands, its `EN n:` follows if Codex is up, then `Stopped.` with no hang; the VAD feeder and sequential decoder both drain before translation shutdown (M9.5).
8. **Transcript persistence** — `uv run live-stt` (no flags), speak, Ctrl+C. Pass: startup prints `Transcript: <repo>/transcripts/<start-time>.txt`; that file holds `[<ISO-8601>] JA n: …` / `EN n: …` lines, one per event, flushed immediately, closed in `finally`. Then `-o /tmp/stt.txt` → same lines appended there, nothing new in `transcripts/`; `--no-save` → prints `Transcript: not saved (--no-save)` and writes no file; a start-then-immediate-Ctrl+C with no speech leaves no new file (lazy creation).

**Soak (1–3 h)** — watch at start and end:
- **Backlog/drops** — meter `q=`/`seg=`/`drop=`/`tdrop=` stay absent (`q=` / `seg=` may blip and clear). A standing `q=Ns` means PCM awaits VAD within `AUDIO_HEADROOM_S`=2 s; `seg=N` means completed utterances await decode within `SEGMENT_QUEUE_MAX`=8; any `drop=N` means the ingestion pipeline fell behind. `tdrop=N` means translation fell behind (`TRANSLATE_QUEUE_MAX`=50, drop-oldest).
- **Thread rotation** — ~every 100 EN turns one `EN` lands a few seconds slower then cadence resumes with no error (codex thread rotation, D-011); EN must keep flowing across the bump.
- **Quota** — out-of-band via `account/rateLimits/read` (not surfaced in-app); expect ≈0 % primary-window movement (D-011). A climbing window → revisit D-011.
- **Memory** (external `ps`/`top`): RSS flat — ring, audio headroom, and segment queue are bounded; `_RESAMPLE_CACHE`≤8; codex `_notes`/`_pending` drain per turn. Steady growth signals a leak.

EN stopping while JA continues is the D-009 JA-only degrade: the 3-consecutive-failure path logs `translation disabled after N…`; a codex EOF in an idle gap logs `codex app-server exited; JA-only…` once and, if a turn is mid-flight, wakes it promptly instead of stalling a window.

- **D-016 — Whisper large-v3-turbo on the NPU under a VAC streaming policy is the default STT path; no prose is ever fed back to the recogniser.** Three measured findings, per-character caption lag, one 4:48 paused narration (N=1383) + M10.5b's 182 s pause-free clip (N=1166). **(a) Policy.** Waiting for silero to close a segment bounds the first character's latency by the last: on pause-free audio silero yields 8 segments of 20–33 s, measuring 15.5 s median / 36.6 s max lag. VAC (silero controlling a LocalAgreement-2 buffer, `streaming.py`) measured 2.5 s / 8.1 s on the same audio and won CER on both corpora and both devices. Pure streaming without the VAD controller *loses* to plain VAD at the median on paused audio (3.18–3.74 s vs 2.43 s) — it bounds the tail, it does not beat pause-triggered emission; VAC is the synthesis. Shipped k2v2+VAD → whisper+VAC on NPU: long_form CER 0.2538→0.2321, retention 0.1587→0.0583 with lag median 14.239→2.483 s. Cost is ~10× decode (RTF 0.041→0.48–0.60), leaving 1.7–2.1× real-time headroom. **(b) Device.** NPU costs nothing in accuracy — unconditioned VAC CER 0.2321/0.0686 vs GPU 0.2292/0.0695 — and forfeits exactly one feature: `libopenvino_genai.so.2026.3.0.0`'s `StaticWhisperPipeline` asserts `'initial_prompt' parameter is not supported on NPU device` and the same for `hotwords`; probed prompt lengths 1/2/4/8/16/32/64/128/200 all raise and 0 passes, so it is a capability gap, not a length budget. `WhisperEngine.set_hotwords` drops the list per device, `--asr-device GPU` unlocks it. User chose the NPU default for efficiency. **(c) Conditioning.** Feeding recent transcript back as prev-text is a landmine: CER 1.8919 on the pause-free clip against 0.1278 unconditioned, 2,126 insertions on 1,166 reference characters, tail repeating one clause 7× — the third reproduction of prompt-induced looping (streaming buffers 0.9328; Kotoba 0.8402). It helps only the paused case (0.2408→0.2054). `CONTEXT_PREV_CHARS` and the carry buffer are deleted. A bounded TERM LIST on the same slot is loop-free and measured 0.2408→0.1873, so terms ride `hotwords`; under the NPU default session context reaches the model through the translator glossary alone. **Honest limits:** the hotwords figures use an ORACLE term list drawn from the reference (an upper bound — passive learning has contributed 0 terms unseeded); long_form absolute CER is inflated by period-vs-modern orthography in the 「ごん狐」 reference, though relative deltas share one reference and normalizer; one clip per corpus; and energy was never measured, because RAPL `energy_uj` is mode 400 `nobody:nogroup` in this container and unreadable even under sudo — NPU-vs-GPU perf/W is a host measurement. A defect found by `tests/test_streaming.py`: `emitted` shrank when a hypothesis retracted, so the next decode re-committed on-screen characters; holding it append-only removed every insertion on retention (I 12→0, CER 0.0686→0.0583).
