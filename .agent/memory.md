## Orientation

**What it is:** real-time Japanese STT + English translation, fully local STT, no API keys (D-009). Pipeline (all in `live_stt.py`, ~1,000 lines, single-file by D-002): mic → `resample` → 2 s `AudioQueue` → silero VAD feeder + `RingBuffer` pre-pad re-slice → 8-segment queue → sequential low-RMS chunked decode (JA, k2v2 default) → `CodexTranslator` (JA→EN over a persistent `codex app-server`, JSON-RPC/stdio, D-011) → `emit_line`. Degrades to JA-only when codex is absent/failing (hard requirement, D-009).

**Known caveats:**
- Models are a runtime prerequisite — `check_models()` preflights and points at `models/README.md`.
- Silero opens segments 0.2–0.7 s late (D-010); every segment is re-sliced from the ring with `VAD_PRE_PAD_S=0.4` lead-in — VAD/worker edits must preserve this.
- Raw long segments (>~15–20 s pause-less) degrade both offline decoders via wholesale deletions; the shipped worker now protects >10 s segments with low-RMS overlapped chunking (L-023). Paused speech + short segments retain the original single-decode path.
- Tool-feature disables in `_CODEX_CONFIG` are THE latency lever (D-011): re-enabling web_search/browser/apps re-injects ~15 K tokens/turn (p50 0.99 s → 3.15 s) — keep them off.
- Codex auth is external state (`~/.codex/auth.json`, check existence only, never read); plan reports `prolite`, Spark entitled regardless (D-011).
- `sherpa-onnx` + `sherpa-onnx-core` (carries libonnxruntime) are both pinned — keep both (uv once skipped the declared sub-dep).
- sherpa online gotcha: `from_transducer(enable_endpoint_detection=…)` surfaces as config `.enable_endpoint`; `OnlineRecognizer.reset(stream)` resets by side effect and returns `None` despite its bool annotation — never branch on the return.
- Benign default-engine STT quirks: ジェミニ→ゼミニ, 文→分 homophone — EN leg translates through them.
- The EN leg needs `codex` on the PATH of the machine *running* live-stt; installs/logins are per-machine, user-only, and a container login does not carry over. Both layers have it now — host installed + EN confirmed live there (second smoke, 2026-07-02).

## Decisions (D-002 … D-014)

ADR-style, compact — active decisions only. When one is superseded, delete it and fold any still-live constraint into the successor; the prior record lives in git + `roadmap.md`.

- **D-002 — Single-file `live_stt.py`.** No package/module split: one dev (agent), one user; splitting buys reuse/isolation we don't need and costs context per file. M9.5 revisited the ~1,000-line threshold: the feeder/decoder stages share config, state, replay hooks, and shutdown order, remain adjacent, and introduce no navigation incident → keep one file. Revisit on an actual navigation failure or a cohesive one-way subsystem boundary.
- **D-004 — `.agent/` shape = the lean memory system.** Current shape: `memory.md` + `roadmap.md` + `polish.md`, all committed (a fresh clone reproduces durable context per `CLAUDE.md`'s long-horizon rule). Those three arrive attached and whole on every session, so they stay minimal; `archive/<record>.md` is the one sanctioned extension — closed-milestone unit detail that a MILESTONE-REVIEW close lifts out of the roadmap, kept outside the attached set and reached through the roadmap summary's pointer. `polish.md` earns a file by lifecycle rather than topic: its rows are consumed and pruned by `/session-polish`, while memory's lines are durable and roadmap's track milestone state. The context gauge is no longer in tree: it is the machine-scoped `context-gauge` in `~/.local/bin`, project-independent and therefore owned by the global scope per `CLAUDE.md`'s routing rule. *Resist re-expanding into per-topic files — the single memory file is the decision, and `archive/` takes closed-milestone detail alone.*
- **D-005 — Superseded-spike docs pruned; the live rationale is the decision log, not in-tree reports.** The Gemini (T3.1) + metered-backends spike reports and the rejected `codex_ws/AGENTS.md` prompt-mechanism were removed from tree at user direction (2026-07-20); git history preserves them. They justified abandoned cloud branches — the actual cloud→local trail is D-009/D-010/D-011 + the roadmap ledger. Do not re-add spike reports for superseded work; record the decision here instead.
- **D-006 — Don't refactor `live_stt.py` for "LLM-readability."** Its optimization comments encode irreplaceable rationale; denser naming saves ~30 tokens at every call-site's expense (L-001). Target a specific confusing line only on a real incident, never the whole file.
- **D-007 — Pre-commit hook via `.githooks/` + `core.hooksPath`, not the `pre-commit` framework.** The hook is one line (`uv run pytest -q`); the framework adds schema + per-hook venv cache + network bootstrap for nothing at this scope. Each clone opts in once (`git config --local core.hooksPath .githooks`). `--no-verify` bypasses for emergencies. Revisit if the hook grows past one or two commands.
- **D-008 — `.claude/settings.json` deny-list.** Denies the do-not-read set in § Orientation to keep secrets, bulk data, and regenerable state out of context. The rule applies at the Claude tool boundary; project scripts may construct and read those paths at runtime (L-016). Keep the list synchronized with `CLAUDE.md` and narrow a rule when a task legitimately needs a blocked path.
- **D-009 — No-API-key architecture: local STT + Codex-subscription translation, Gemini replaced outright.** Trigger: user wants a Codex subscription, no API keys. Supersedes the Gemini backend (T3.1/T3.2), kills T-BACKENDS-001. STT leg = local CPU-only streaming JA engine (D-010); translation leg = Codex subscription text surface via the sanctioned persistent CLI (D-011), chosen over the undocumented backend endpoint and over Codex `[realtime]` voice (agentic-loop-wrapped, 60 s-capped — unfit as a transcriber). Local MT rejected by user (wanted GPT-quality EN at zero marginal cost). Consequences: endpointing/VAD returns to the app (silero); new runtime dep on codex CLI + OAuth; **graceful JA-only degradation is a hard requirement**. Revisit if a subscription-auth realtime audio surface becomes sanctioned, or local CPU JA quality proves insufficient (try larger local models before any metered API).
- **D-010 — STT engine: reazonspeech-k2-v2 default, parakeet-ja A/B alternate (both via sherpa-onnx).** *(README/models/README cite this for engine-selection rationale.)* Measured (5 clips, 8-core CPU, int8-enc+fp32-dec for k2): both TTFT ≤0.10 s post-audio (Gemini baseline 1.21 s), $0/hr. Default **k2-v2**: RTF 0.054 vs 0.106, 148 MB vs 625 MB, Apache-2.0, JA-specialist, kanji-rich output. Keep **parakeet** selectable (slightly better published CER, wins the 文 homophone) — same sherpa integration, near-zero cost to retain. Two findings shape the live path: (1) **silero onset clipping** — segments open 0.2–0.7 s late, sherpa exposes no pad field → re-slice each segment from the fed-sample ring with `VAD_PRE_PAD_S=0.4`; (2) **raw long segments collapse decode** — segment LENGTH (>~15–20 s pause-less), not synthetic-vs-real audio, causes wholesale deletions (L-023) → keep the soft VAD cap at 20 s but split >10 s decode input at low-RMS windows. M9.4 re-evaluated the engine decision after the shared fix: k2v2 CER 7.8/11.4 % vs parakeet 8.9/12.1 % on long/medium stressors, both with ≤0 % excess deletion; k2v2 therefore remains default on accuracy plus its size/licensing/short-decode advantages. T-XLAT-ATTRIB-001 adds downstream evidence the CER aggregates could not: judged EN adequacy over whole-clip hypotheses puts parakeet +0.126 [+0.019, +0.227] ahead of k2v2 and nearly halves severe failures (`adequacy≤2` 10.6 % → 5.9 %), while the ASR error profile shows parakeet winning 354/532 FLEURS utterance-level disagreements (paired ΔCER −4.450 pp [−5.596, −3.333]) and cutting >20 % CER rows 22.15 % → 15.23 %. Counter-signal: parakeet's `confident_error` rate is higher (0.260 vs 0.229) — fewer wrecks, subtler substitutions. k2v2 remains the shipped default only because the switch is a pending user decision (`roadmap.md`), not because the evidence still favors it; `--engine parakeet` works today. Revisit if Reazon ships native-streaming JA or proper-noun drift proves disruptive.
- **D-011 — Translation leg: codex app-server, `gpt-5.6-luna` + low effort, "Fast" service tier, `developerInstructions`, tool features off.** *(README cites this for the translator's latency + injection-resistance.)* Surface: persistent `codex app-server` subprocess, newline-delimited JSON-RPC/stdio — `initialize` → `thread/start` (one thread/session, `ephemeral`, `sandbox:read-only`, `approvalPolicy:never`, `personality:none`) → `turn/start` per block → `agentMessage` deltas → `turn/completed`; quota via `account/rateLimits/read`. Five binding choices: (1) model `gpt-5.6-luna` + `effort:low`, selected by the tournament below (runner-up `gpt-5.6-terra`+`medium`); (1b) **`serviceTier:"priority"` on thread/start** = Codex's "Fast" tier (`model/list` advertises it for Luna as id `priority`, name "Fast", "1.5x speed, increased usage"; the CLI also accepts the display alias `"fast"` and normalizes it to `priority`). Set per thread — user directive 2026-07-21 was to get Fast in this tool *without* changing global settings, and `~/.codex/config.toml` keeps `service_tier="default"` untouched. `_new_thread` sends it on the startup thread and on every ~100-turn rotation, so warm-up + every caption turn ride it. **An unrecognized tier is silently dropped** (thread/start succeeds, echoes `serviceTier:null`, no error), so the code compares the echo and logs one warning rather than assuming it landed; `"default"` (or an explicit null) echoes `'default'` = the standard tier. Live-verified end to end: sent `priority` → applied `priority` on both the initial and rotated thread, 5/5 real turns translated, median 1.70 s. Tradeoff to watch: "increased usage" burns the shared bucket faster than (4)'s token counts alone imply; (2) **disable tool-injecting features at spawn** (web_search/image/browser/computer/apps) — THE latency lever: tool schemas were ~15 K tokens/turn, p50 3.15 s → **0.99 s**; (3) role pinned via `developerInstructions` on thread/start — injection-resistant (imperatives in the speech get translated, not obeyed; AGENTS.md-in-cwd mode was rejected — Spark obeyed "delete all files"); (4) marginal cost ≈180 in + 7–60 out tokens/turn, ~50 turns moved the 5 h window ~0 %; Luna bills the shared `codex` limit bucket, where Spark had a dedicated `codex_bengalfox` one, so translation now competes with ordinary Codex usage for quota (~1,300 turns ≈ 1 pp of the weekly window). Live notes: thread grows ~30 tok/turn → rotate every ~100 turns (one ~2.7 s uncached turn); `error` notifications with `willRetry` → degrade JA-only. Degradation guarantees (locked by `tests/test_translator.py`): a >64 KiB line, broken transport, or EOF routes into cleanup that enqueues one `{method:error}` sentinel onto `_notes` — a turn parked mid-collect then raises at once instead of waiting out `TRANSLATE_TIMEOUT_S`; the enabled→disabled flip logs once; `submit` counts backlog evictions into `dropped_translations` (meter `tdrop=`, >0 only). `start()` re-checks `_reader_task.done()`/`returncode` before enabling, so a warm-up death can't strand later turns over a dead reader (L-022). Model/effort tournament (30-item production-shaped JA corpus = real k2v2 hypotheses + 4:48 narration segments + injection probes; 12 configs × 3 reps = 1,110 turns through the exact `_CODEX_CONFIG`/`developerInstructions`/thread options; blind anonymized grading, 4 passes over 2 judge models): **`gpt-5.6-luna`+`low` won and is now the default** — median 1.38 s [1.31, 1.52], quality 4.83/5, contract 1.98/2, 0 format violations, 0/90 failed turns; reproduced at median 1.38 s driving the real `CodexTranslator`. Effort is near-inert here: paired quality vs `low` shifts ≤+0.06/5 across Terra low→ultra and Luna low→max, and only Luna xhigh/max clear zero, buying +0.06 for +0.6–1.1 s median. Terra ≈ Luna on quality (4.840 [4.816, 4.862] vs 4.853 [4.824, 4.879]), runs 0.1–0.3 s slower at matched effort, and holds contract 1.99 at every level while Luna dips to 1.92–1.94 above `low` (keeps quoted JA terms inside the EN line). ## Lessons (L-001 … L-027)

Generalizable rules from past mistakes/findings — active only. Tests cite L-004. Delete a lesson once obsolete or folded into another; git holds it.

- **L-001 — Don't over-edit optimized code for "LLM-readability."** Keep comments that encode a non-obvious invariant/optimization and naming that's already domain-aligned; only edit when you can name a specific failure mode the edit prevents.
- **L-004 — Mic and real-terminal paths are agent-unverifiable.** The sandbox has no mic/interactive TTY. Any change touching `sd.InputStream`/`audio_callback`/real-time latency/Ctrl+C/multi-hour behavior gets a "**Did not verify**" list (see § Smoke) naming each path for the user; do not claim "done" without it.
- **L-005 — Avoid abstractions in `live_stt.py`.** Trajectory is consistently "less code wins"; default to inlining, no config/DI/plugins/class hierarchies unless the task requires them.
- **L-006 — TTY-gate the cursor-clear (`\r\x1b[2K`) protocol per stream, evaluated once.** stderr: the `logging.Formatter` prepends it gated on `sys.stderr.isatty()` so redirected logs are ANSI-free — the rare ~10-line subclass that beats inlining (vs L-005). stdout: the meter status line + `emit_line` gate on module-level `_STDOUT_TTY = sys.stdout.isatty()`, so redirected stdout stays ANSI-clean and the meter is silent off-TTY; any new stdout status writer gates the same way.
- **L-008 — A single user preference is state, not an "always" rule.** Record placement/config choices as *current state* with their decision source, not as `always`/`never` laws; ask before reversing a user-set arrangement. Reserve firm lessons for technically-derivable facts.
- **L-010 — Keep device-backend imports at device entry points; check a dlopen'd native lib by importing its binding.** PortAudio probes host audio controls during `sounddevice` import; eager app-module import can hang model-only evaluators on an unhealthy device. `run_session` + `--list-devices` own the imports; offline replay/test stays hardware-independent. This container's `ld.so.cache` is empty yet libs resolve fine; verify mic prerequisites with `uv run python -c "import sounddevice"` or `dpkg -l libportaudio2`, not `ldconfig -p`.
- **L-016 — Deny-listed paths block tool arguments, not a script's runtime `open()`.** Claude's project deny-list refuses matching Read/Edit/Bash targets; a committed project script that constructs the path internally can still consume the data. Use the existing manifests/tooling for deny-listed corpora rather than exposing bulk inputs directly.
- **L-017 — Corpus evidence = pinned payloads → canonical PCM → content-addressed index.** Dataset Viewer `/rows` lacks a revision selector and can disappear; acquire revision-addressed files directly, verify size + SHA-256 on fresh/cached paths, parse the declared schema, then stage every decoded row before installing an index-addressed cache directory and committing its compact fingerprint last. Pin transient decoders + the expected whole-index hash: package drift becomes an explicit requalification, not silent evidence churn. M10.2 applies this to complete Common Voice Parquet + FLEURS TSV/tar; the ignored JSONL carries row identity/reference/duration/PCM hash, while git carries provenance/distributions/attribution. Count repeated references/audio; uniqueness is a result, not an assumption.
- **L-018 — Maintenance-pass recipe.** Inventory `uv tree --outdated --depth 1` → CVE scan `uv export --format requirements-txt --all-groups --no-emit-project >/tmp/reqs.txt && uvx pip-audit -r /tmp/reqs.txt` (pip-audit scans its own env — feed it the export) → apply lock-only bumps (`uv lock --upgrade-package NAME`) unless the older declared floor is unsupported/security-blocked, in which case raise it deliberately → full gate (import, pytest, ruff, `uvx pyright@1.1.410`) → re-verify the codex leg (not in pytest) via a synthetic `CodexTranslator` turn (`start()` warm-up + `_translate`). Keep package versions out of memory (drift risk).
- **L-019 — A refactor pass on mature, guarded code may correctly yield almost nothing.** Screen each candidate against L-001 ("name the failure mode prevented"); land only those with a nameable win or house-style fix, record the rejected ones in `roadmap.md` so they aren't re-litigated. "Mature; minimal change" is an honest result — don't manufacture edits (pink-elephant pull).
- **L-020 — Roadmap-generation via workflow: the adversarial screen is the deliverable, not the ideation.** Force every finder to read the real code/memory first (ungrounded agents propose out-of-scope textbook features); gate each candidate through a reviewer carrying the project's own laws; record rejects; report a small high-conviction list; verify the highest-stakes survivors against live code yourself and write units by symbol/behavior (line refs drift).
- **L-021 — `CLAUDE.md`'s "For humans: hyphens over other dashes" / de-LLM-smell rule applies to human-facing surfaces only.** Edit only `README.md` and the user-facing CLI strings in `live_stt.py`; leave `.agent/*`, `roadmap.md`, `CLAUDE.md`, code comments, and Claude workflow files (em-dashes deliberate there). Confirm with `grep -nP '[\x{2013}\x{2014}]' README.md`; keep any literal duplicated across code and README in sync.
- **L-022 — Adversarial-review follow-through: fix with a non-vacuous lock, and record the rejects.** Codex Finding 1 (HIGH) surfaced an "enable-over-corpse" startup race (a warm-up/health check that completes just before an async child dies can flip you "live" over a finished reader). Durable pattern: **validate liveness at the commit point** (re-check `_reader_task.done()`/`returncode` immediately before `enabled=True`), not only at spawn. Two reusable test techniques: (a) **deterministic async-EOF** — buffer every response line AND `feed_eof()` in one synchronous burst before the read loop drains; `StreamReader.readline()` returns without yielding when a line is already buffered, so EOF is guaranteed processed before the code under test reads liveness. Answer control requests reactively through `_read_loop` (`_await_pending(rid)` → feed the result line) rather than reaching past it with `set_result` — exercises the real dispatch path. (b) **Prove non-vacuity** — neutralize the fix (`if False and …`), watch the new test fail with the exact bug, restore. Record rejected findings with the reason so they are not re-litigated: Finding 2 (the EOF *cleanup* logs once; a rare second ERROR is `_translate`'s 3-strike branch — distinct, correct, already commented) and Finding 4 (`close()` runs only after `translator_task` ends, so no `_turn` is mid-collect — the no-sentinel claim is correctly scoped) were both rejected as code changes.

- **L-023 — Long continuous speech defeats soft caps and offline decoders; test with a genuinely-continuous stressor.** sherpa's silero `max_speech_duration` (default 20 s) raises the threshold (0.5→0.9, min_silence→0.1 s) instead of hard-cutting — dip-less speech grows unboundedly, so VAD tuning alone cannot bound segment length. Offline attention/transducer models delete content wholesale past ~15–20 s; segment LENGTH, not synthetic-vs-real audio, is the degradation axis (D-010's "TTS collapse" was this), engine-dependent — k2v2 collapses ~3–4× harder than parakeet before mitigation. Build a continuous stressor from real short clips via silero-trimmed speech extents + ~10 ms equal-power crossfade joins (gap-concat leaves clip-edge quiet the VAD rightly splits on); the trim costs onset deletions on isolated decode (silero opens late; 0.4 s pre-pad recovers) → record a per-component baseline and report EXCESS deletion (stressor D − Σ baseline D), else the stressor measures its own construction artifact. Measured construction/QC numbers + WAV sha256 live in `tests/stressor_clips.json`; current shipped-pipeline scores live in `tests/cer_baseline.json`. Prove the corpus honestly, not by loose proxy (`n_seg < n_comp` is gameable — passes at 14/15): continuity = every crossfade-join offset sits inside a cap-OFF VAD segment; soft-cap causality = cap-ON yields more segments than the cap-OFF control. Fix lesson (M9.4): lowering the soft cap 5–12 s still leaves 9–16 s blocks and adds harmful reset boundaries; retain 20 s endpointing, preserve ≤10 s input by identity, then split only longer decode slices into balanced ~2 s low-RMS views with small overlap + conservative exact text merge. Gate total CER alongside deletion so overlap duplication cannot game the deletion target. Genuine narration answers a different question: M9.6's 4:48 chapter naturally endpoints to a ≤9.686 s resliced upper bound, validating long-session completeness but not the >10 s split — keep the continuous stressor as the split-path gate. The committed pause-free gate is 44.7 s; do not claim arbitrary duration because one VAD segment surviving beyond `RING_SECONDS`=60 loses its unretained head. Gotcha: `max_speech_duration` × 16 kHz is an int32 sample count — a huge sentinel (≥~1e6 s) overflows → spurious splits; the control 'off' is a cap just above audio length (`make_vad(max_speech_s=120)`).

- **L-026 — A model bench is only evidence if the harness mirrors production failure handling and the judge sees raw candidates.** Import the real config/instructions/thread options rather than retyping them, and copy the production cleanup path: a `codex app-server` turn that times out keeps running server-side, so without `turn/interrupt` + note drain one stall silently converts every later turn into a timeout — a 5-turn "model failure" that is really one stall plus a harness defect. Present judge candidates between explicit `[Cn]`/`[/Cn]` markers, never through `repr()`/quotes: quoting every candidate makes each look like it added quotes and caps the format-contract score for the whole field at once. Interleave repetitions across configs (rep1 all configs, then rep2) so server-load drift hits every config alike, run configs sequentially so latency stays uncontended, and compare tiny quality gaps paired on the same (item, rep, judge) grading with a bootstrap CI — marginal means put a config "ahead" at differences a paired CI shows as zero.

- **L-027 — A deterministic content probe measures your regex until you read the misses.** Per-item `must`/`forbid` regexes catch real content loss cheaply and objectively, but nearly every early miss was the pattern, not the model: spelled-out numbers ("six units"), hyphens ("stage-two", "12-unit"), synonyms ("decreased" vs "reduced wall motion"), analyte variants ("PaCO2" vs "pCO2"), reversed negation order ("resuscitation will not be performed" against a pattern demanding `not` before `resuscitat`), and legitimate alternate renderings (the Japanese brand "Predonine"). Two habits make the layer trustworthy: (a) validate every pattern against an authored reference translation at corpus-build time and fail the build on mismatch — this catches inverted/typo'd patterns before any turn is spent; (b) treat each first-run miss as a suspect regex and read the actual output before recording it as a model error. Five loosening rounds took 702 turns from ~20 apparent content failures to 7 real ones. Keep every loosening synonym-only, so a wrong dose, side or negation still fails. Mirror trap, and the more dangerous one: a *passing* pattern can hide a real defect. `must.drug` = `prednis|predonine` passes for prednisolone AND prednisone — different molecules — so the declared probe and the aggregate quality scores both scored the wrong-drug turn as clean; only an explicit discriminating check found it. Once a defect is named, write a check that separates it from the correct output instead of reusing the declared pattern, and A/B against that check rather than against the aggregate. Corollary from the instruction probe: attribute a fix to the line that causes it — run one arm per candidate line cumulatively, since the drug-only arm showed the drug line does nothing for gender.
- **L-024 — Backpressure capacity is time; prove it with paced production replay.** Callback block sizes are backend-selected, so a block-count queue cannot express audio headroom; bound queued PCM seconds directly. Fast-as-possible file replay also cannot expose real-time serialization: pace production arrivals on a virtual sample clock, replace only decode cost, and retain the production worker/VAD/ring/queue/drop policy. Keep feeding separate from sequential decode, copy ring slices before queueing them, bound both stages, and failure-couple siblings; otherwise a slow decode either blocks VAD ingestion, lets later ring writes corrupt queued views, or strands a stage after its peer dies. Pair the deterministic stress with live meter/soak checks: modeled timing proves the known workload, not arbitrary host scheduling.

- **L-025 — Evaluator completeness is input/event accounting, not nonempty text.** On the complete short corpus, both offline controls consumed every sample + EOF exactly once yet shared 10 identical empty hypotheses with `segments=[]` (quiet/short material rejected by the common production VAD). These are completed ASR misses → retain the case IDs and score D=N. A failed/partial corpus run means missing/duplicate/reordered IDs, unconsumed audio, wrong EOF/finalization, or a worker exception; it never means one completed clip emitted no text. Keep “nonempty run” corpus-level, or a shared frontend can make every downstream candidate fail by construction. Backend-declared generation/context truncation is a third state: the input run completed, but the output is knowingly terminal-limited → capture native diagnostics per phase/case and fail a separate deterministic content gate instead of relabeling completion or silently scoring the warning away. Publish only exact indexed runs; detailed hashes + aggregate atomicity prevent partial evidence from masquerading as a model result.

- **L-028 — A parallel-corpus reference is a judge-validity probe, never a translation ceiling.** FLEURS EN and JA are independent renderings of a shared source, so neither is a translation of the other and the JA routinely carries specificity the EN drops (`胡氏` → "He"). Scored blind against the JA source, the human EN reached adequacy 4.255/5 while MT over the *perfect* JA transcript reached 4.880 — report that gap as a property of the corpus, never as "MT beats human." Two durable consequences. (a) The low human score is the payoff, not a defect: a judge that docks fluent, human-authored English for diverging from the source is demonstrably grading content rather than rewarding fluency, which is exactly the assurance an adequacy claim needs — so keep the reference in the blind field and read it as instrumentation. (b) String metrics against such a reference are bounded far below their nominal maximum for correct output (oracle chrF2++ 57.75), so use them to rank arms sharing one reference and never as an absolute quality level. Generalize: when a "gold" candidate scores near the system under test, suspect the gold's provenance before crediting the system.

## Smoke checklist — agent-covered vs user-only (L-004)

**Agent-covered (M9):** the two-engine replay/CER gates own short-transcript stability, genuinely-continuous >10 s decode behavior, and the full-file 4:48 narration path. Paced production replay owns the 44.722 s / 20 ms callback / decode-RTF 0.20 backpressure case (max audio queue 0.020/2.000 s, segment queue 1/8, `drop=0`) plus all 7 short clips. Pure tests own drain-on-shutdown, sentinel landing, stage-failure cancellation, and translator degradation. These gates exercise the real worker but not a microphone driver, OS signal timing, real Codex happy path, or elapsed multi-hour behavior.

**User-only boundary:** mic capture, device select, latency feel, real Ctrl+C flush, `-o` persistence, Codex cadence, and multi-hour soak. This is the fixed procedure a "Did not verify (L-004)" disclaimer points at; each item names the `live_stt.py` observable that decides pass/fail. **Setup:** models downloaded; `codex` installed on the `PATH` of the machine/environment running live-stt; `codex login` there once for the EN leg (without it: `Translation: unavailable — JA-only`, EN checks N/A). One utterance = speech + a ≥0.5 s pause (`VAD_MIN_SILENCE_S`).

**Live-mic pass (~5 min):**
1. **Devices** — `uv run live-stt --list-devices` lists the `sd.query_devices()` table and exits. Pass: your mic shows with input channels.
2. **Capture + backlog** — `uv run live-stt`, speak. Pass: `JA n:` lines print (capture + decode live); `q=` / `seg=` are absent or brief and clear after each utterance; any `drop=N` fails.
3. **Device select** — `uv run live-stt --device N`. Pass: prints `Mic: #N <name> @ <rate> Hz`; capture works as in (2).
4. **Latency + endpointing** — one sentence, then stop. Pass: `JA n:` prints ~0.6 s after you stop (0.5 s `VAD_MIN_SILENCE_S` + ~0.1 s decode, D-010); a brief mid-sentence pause does not split it.
5. **Translation cadence** — Codex up. Pass: each `EN n:` trails its `JA n:` by ~1 s, shared `n` keeps pairs matched; `--no-translate` suppresses every EN line.
6. **Ctrl+C mid-utterance** — start speaking, Ctrl+C while still talking. Pass: the in-progress `JA n:` still prints (worker flushes the VAD in `finally`), its `EN n:` still lands if Codex is up (translator drains last), then `Stopped.` with no hang (non-blocking shutdown sentinel, T8.1).
7. **Ctrl+C mid-decode** — run `uv run live-stt --engine parakeet`, speak continuously for >20 s, pause, then press Ctrl+C immediately while the slower long-block decode is running. Pass: that block's `JA n:` still lands, its `EN n:` follows if Codex is up, then `Stopped.` with no hang; the VAD feeder and sequential decoder both drain before translation shutdown (M9.5).
8. **`-o` persistence** — `uv run live-stt -o /tmp/stt.txt`, speak, Ctrl+C. Pass: file holds `[<ISO-8601>] JA n: …` / `EN n: …` lines, one per event, flushed immediately, closed in `finally`.

**Soak (1–3 h)** — watch at start and end:
- **Backlog/drops** — meter `q=`/`seg=`/`drop=`/`tdrop=` stay absent (`q=` / `seg=` may blip and clear). A standing `q=Ns` means PCM awaits VAD within `AUDIO_HEADROOM_S`=2 s; `seg=N` means completed utterances await decode within `SEGMENT_QUEUE_MAX`=8; any `drop=N` means the ingestion pipeline fell behind. `tdrop=N` means translation fell behind (`TRANSLATE_QUEUE_MAX`=50, drop-oldest).
- **Thread rotation** — ~every 100 EN turns one `EN` lands a few seconds slower then cadence resumes with no error (codex thread rotation, D-011); EN must keep flowing across the bump.
- **Quota** — out-of-band via `account/rateLimits/read` (not surfaced in-app); expect ≈0 % primary-window movement (D-011). A climbing window → revisit D-011.
- **Memory** (external `ps`/`top`): RSS flat — ring, audio headroom, and segment queue are bounded; `_RESAMPLE_CACHE`≤8; codex `_notes`/`_pending` drain per turn. Steady growth signals a leak.

EN stopping while JA continues is the D-009 JA-only degrade: the 3-consecutive-failure path logs `translation disabled after N…`; a codex EOF in an idle gap logs `codex app-server exited; JA-only…` once and, if a turn is mid-flight, wakes it promptly instead of stalling a window.
