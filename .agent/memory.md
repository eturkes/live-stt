## Orientation

**What it is:** real-time Japanese STT + English translation, fully local STT, no API keys (D-009). Pipeline (`live_stt.py` ~1,470 lines + `streaming.py`, D-002): mic → `resample` → 2 s `AudioQueue` → silero VAD → **VAC controller** (speech-start opens a LocalAgreement-2 buffer in `streaming.py`; every `VAC_CHUNK_S` re-decodes the open buffer and commits what two decodes agree on; speech-end flushes the tail unconfirmed) → **whisper large-v3-turbo int8 on OpenVINO NPU** (D-016) → `CodexTranslator` (JA→EN over a persistent `codex app-server`, JSON-RPC/stdio, D-011) → `emit_line` → stdout + the per-session `transcripts/` file (saved by default). Partial text renders on the meter status line; one utterance = one numbered `JA` line = one translation turn. `--engine k2v2|parakeet` selects the **sherpa fallback path** (VAD-segment close → ring pre-pad re-slice → 8-segment queue → sequential low-RMS chunked decode, D-010); `--asr-device` selects the OpenVINO device for the default engine. Degrades to JA-only when codex is absent/failing (hard requirement, D-009).

**Known caveats:**
- Models are a runtime prerequisite — `check_models()` preflights and points at `models/README.md`.
- Silero opens segments 0.2–0.7 s late (D-010); every segment is re-sliced from the ring with `VAD_PRE_PAD_S=0.4` lead-in — VAD/worker edits must preserve this.
- Raw long segments (>~15–20 s pause-less) degrade both offline decoders via wholesale deletions; the shipped worker now protects >10 s segments with low-RMS overlapped chunking (L-023). Paused speech + short segments retain the original single-decode path.
- Tool-feature disables in `_CODEX_CONFIG` are THE latency lever (D-011): re-enabling web_search/browser/apps re-injects ~15 K tokens/turn (p50 0.99 s → 3.15 s) — keep them off.
- Codex auth is external state (`~/.codex/auth.json`, check existence only, never read); plan reports `pro`, Spark entitled regardless (D-011).
- `sherpa-onnx` + `sherpa-onnx-core` (carries libonnxruntime) are both pinned — keep both (uv once skipped the declared sub-dep).
- sherpa online gotcha: `from_transducer(enable_endpoint_detection=…)` surfaces as config `.enable_endpoint`; `OnlineRecognizer.reset(stream)` resets by side effect and returns `None` despite its bool annotation — never branch on the return.
- **`VoiceActivityDetector` owns two buffers with different drain rules; every feeder must pop.** Closed segments queue up in `segments_`, each owning a copy of its audio, and `pop()` is the only drain the Python binding exposes (no `clear()`) ⇒ a consumer that never pops retains **~3.8 MB per speech-minute** (measured undrained over 848 s of narration: 214 segments = 39.4 MB, RSS +49.7 MB). `pop()` touches that queue alone — model, `start_` and sample buffer untouched — so `is_speech_detected()` is bit-identical with a drain in place (measured: same sha256 over 26.5 K windows), which is why draining costs the VAC path nothing. Its OTHER buffer (the `buffer_size_in_seconds`=60 sample ring) is popped only on a **non-speech** window, so >60 s of unbroken speech logs `circular-buffer.cc:Push … Overflow!` and DOUBLES it — lossless, bounded by the longest speech run, and **unrelated to the segment queue**: no drain prevents that line.
- Benign default-engine STT quirks: ジェミニ→ゼミニ, 文→分 homophone — EN leg translates through them.
- **`whisper/long`'s golden pins a real duplication (`…に送ってに送って…`) — CLOSED, do not re-derive or re-fix (user ruling 2026-09-02, two measured attempts).** Root cause: `streaming.py`'s `emitted` is a character count re-derived from the latest hypothesis, but it must denote what was PUBLISHED. `process()` pins `stable = max(agreed, len(self.emitted))` then assigns `self.emitted = text[:stable]`, so a decode that RE-SPELLS an already-published prefix at the same character length silently re-anchors the boundary to earlier audio; `finish()` then flushes `previous[len(emitted):]` a second time. Instrumented NPU replay of `long.wav`: 13 updates, **0 trims** — not a trim effect, and D-016(d)'s append-only fix covers only the SHRINKING case. Not inherent to LocalAgreement-2; the policy is fine, the bookkeeping is wrong. Both fixes cost more than the artifact: a `startswith` commit guard starves `_trim` (max_buffer 11.248 → 23.9/25.5 s, **RTF 1.15**, above real time), and an audio-time cut at `finish()` traded 4 duplicated characters for 6 dropped ones (retention CER 0.0583 → **0.0635**, D 35 → 41). The second attempt is preserved whole on branch `attempt/p009-audio-time-cut` @ `bd37bf7`. A third attempt must first separate a genuine re-spelling from ordinary span jitter — 6 of 157 commits move backward, median 0.084 s / max 0.452 s, against the ~0.7 s real re-spelling — and would be a funded roadmap unit, not polish.
- **Live-audio repetition loops are M13, not P-009 above — CAUSE FOUND, FIXED, and the repro is
  free.** The recogniser is pinned to Japanese, so audio it cannot account for is emitted as
  Japanese tokens until the model hits `max_length`=448 — exactly the 444-char captions in the live
  logs. The trigger is **not** laughter and **not** room tone: synthetic non-speech (digital
  silence, −60 dB noise, 60 Hz hum) reproduces the hallucination PHRASES
  (`ご視聴ありがとうございました`) but not the loop, while **English speech loops it every time**.
  **Repro, no artifact needed:** `curl -sSL -o .scratch/jfk.flac
  https://raw.githubusercontent.com/openai/whisper/main/tests/jfk.flac` (11 s JFK inaugural, public
  domain), resample 44.1k→16k, pad 1 s silence each end, `replay.py --engine whisper` ⇒ segment 3 is
  a 528-char loop at **RTF 1.106** (a runaway costs more than real time). `soundfile` is not in
  `.venv` — add `--with soundfile` to read the FLAC. Fix = M13.2: `ASR_REPETITION_PENALTY`=1.2 at
  decode + `caption_defect()` dropping the caption at publication.
- **`repetition_penalty` is the ONLY repetition knob that reaches this NPU build.**
  `no_repeat_ngram_size` is accepted and then **silently ignored**: sizes 2/3/4/5/8 all return
  byte-identical baseline text on a clip repeating a 5-char unit ~140×. `num_beams=2` raises
  (`zero_remote_tensor.cpp:259`). The penalty's knee is sharp — 1.15 leaves a 510-char loop intact,
  1.2 takes it to 0, 1.25 buys nothing more. `return_timestamps=True` markedly reduces (never
  eliminates) looping versus `False` on the same audio.
- **`WhisperPipeline` LATCHES its language for the life of the instance.** `generate(language=…)`
  persists into every later call, and after an AUTO-DETECT call the detected language is latched
  too. Proven: fresh→EN = `en`; fresh→JA then EN = `ja`,`ja`; fresh→EN then JA = `en`,`en`. Neither
  `language=None` nor `''` clears it (both raise), nor does `set_generation_config()`, nor passing a
  config positionally to `generate()`. **Only a fresh `WhisperPipeline` re-detects** — so any
  per-utterance LID gate costs one construct per utterance (measured over 40: 0.46 s p50 / 0.60 s
  max construct + 0.54 s detect, RSS flat at 201 MB). Whisper LID itself is reliable on the NPU from
  1 s of audio, but **silence and −30 dB noise both detect as `en`**.
- `result` fields on `ASRDecodedResults`: `chunks, language, perf_metrics, scores, texts, words`.
  There is no `og.WhisperDecodedResults`.
- **A repeated short unit makes the TRANSLATOR generate without terminating; M13.1 screens it out in
  `CodexTranslator.submit`.** Measured through the real app-server, fresh thread per turn, 30 s
  bound, canary control after every degenerate turn (25 rows, every canary 2.8-7.0 s): `"あ"+"は"*n`
  runs 2.9 s at 20 chars and 3.4 s at 60, then **stalls at 120/240/480**; `中央の`/`クラブの`/`アーメンの`
  survive 240 (4.6-10.8 s) and **all stall at 480**; real speech scales flat to **7.0 s at 480
  chars**. So it is repetition, not length, and not only single characters. The screen declines a
  caption whose longest adjacent repetition of a unit ≤`CAPTION_REPEAT_UNIT_CHARS`=8 reaches
  `CAPTION_REPEAT_MAX_CHARS`=40, BEFORE the queue ⇒ `_turn`, `_failures` and `observe_en` are
  untouched by construction and a runaway streak of any length costs no strike. **M13.2 demoted it
  to a BACKSTOP** — `caption_defect()` now drops such a caption at publication, so on the shipped
  path `tskip=` stays 0. Probe inputs are literals ⇒ reruns with no artifact:
  `tests/eval_translate_repeat.py`.
- **Both caption thresholds are corpus-picked against 1073 live JA captions (6 sessions) and both
  sit in an EMPTY gap** — `transcripts/*.txt` is gitignored, so these numbers are the durable
  record; re-derive by parsing `[ts] JA n: text` lines. Repetition: 26 dropped, smallest carrying
  **252** repeated chars, longest survivor **32** (`3 months`×4, itself English) ⇒ 40 has a 6×
  margin either way. In tree the longest repetition is **8** (ポンポンポンポン) over 215 NPU captions +
  all golden texts + 6.9 K chars of Aozora, and widening the unit bound to 20 starts catching a
  speaker repeating a PHRASE (`、うなぎが食べたい`×2, 18 chars). Language: the 23 latin-dominant
  captions split cleanly — 18 true English at ≤0.15 Japanese-per-character, 6 Japanese-carrying-
  loanwords at ≥0.27, nothing between. A 1:1 rule (`latin > japanese`) therefore drops **5 genuine
  Japanese captions** (`Discordで送ります。` 7v5, `HDMIはどう?` 4v3, `A&M Studioですね。` 8v3,
  `HTMLあるんで HMADの中で` 8v7, `…quantizationは、precisionの、そして、` 21v16), because a Latin letter
  is one phoneme where a Japanese character is a whole syllable, so one loanword outnumbers the kana
  around it. `CAPTION_LATIN_RATIO`=4 cuts that gap at 0.20. Combined drop rate **4.0 %**.
- **The translator is NOT the quality bottleneck — the recogniser is.** Reading 30 consecutive JA/EN

## Lessons (L-001 … L-032)

Generalizable rules from past mistakes/findings — active only. Tests cite L-004. Delete a lesson once obsolete or folded into another; git holds it.

- **L-031 — Size work by the decisions it forces, not by its line count.** Measured over six closed M11 units: Spearman **-0.395** between insertions and context cost (n=6, descriptive), and the extremes invert — the smallest unit by lines (254) was the only one to overrun a window (240K then), while the largest (1,725) was the cheapest. The real predictor is decisions originated inside the work: the cheap unit had its whole surface enumerated before it started, the expensive one hit two unmapped collisions at the gate. Rule: one independently closable deliverable at a time, and split when a piece would force more than a couple of its own design rulings. Never write a "close on partial acceptance if you run out of room" clause — it relabels a known overrun as a plan.
- **L-032 — Keep assurance proportional to the artifact; measure the ratio periodically.** This repo reached ~11,100 lines of verification apparatus around a 2,108-line personal tool: an AST-closure contract fingerprint whose only job was to REFUSE a cached rebuild, a 40-row claim registry validating citations for prose the same author wrote, mutation testing to prove the tests were not vacuous, and a model-tournament stack for a decision already made outside it. The tell was mechanical and visible three units before it was acted on: **the fingerprint needed a hand-written, individually-pinned migration clause in three consecutive units**, each one waving through a legitimate code change. A guard that must be escaped every time it fires is not a guard. Ask what re-checks a defect for free and at what cost (`CLAUDE.md` assurance tiers): for a single-user tool, a fast test suite, a replay golden answering "did the output change", and a scoring script run on demand cover it, while provenance machinery costs more than the defects it catches. The cut deleted 21,038 lines and took the suite from 466 tests / 48 s to 207 / 14.6 s with **zero production change**.
- **L-001 — Don't over-edit optimized code for "LLM-readability."** Keep comments that encode a non-obvious invariant/optimization and naming that's already domain-aligned; only edit when you can name a specific failure mode the edit prevents.
- **L-004 — Mic and real-terminal paths are agent-unverifiable.** The sandbox has no mic/interactive TTY. Any change touching `sd.InputStream`/`audio_callback`/real-time latency/Ctrl+C/multi-hour behavior gets a "**Did not verify**" list (see § Smoke) naming each path for the user; do not claim "done" without it.
- **L-005 — Avoid abstractions in `live_stt.py`.** Trajectory is consistently "less code wins"; default to inlining, no config/DI/plugins/class hierarchies unless the task requires them.
- **L-006 — TTY-gate the cursor-clear (`\r\x1b[2K`) protocol per stream, evaluated once.** stderr: the `logging.Formatter` prepends it gated on `sys.stderr.isatty()` so redirected logs are ANSI-free — the rare ~10-line subclass that beats inlining (vs L-005). stdout: the meter status line + `emit_line` gate on module-level `_STDOUT_TTY = sys.stdout.isatty()`, so redirected stdout stays ANSI-clean and the meter DRAWS nothing off-TTY; any new stdout status writer gates the same way. Gating the writer is not the same as gating the information: the meter's counters exist only there, so off-TTY they move to stderr as high-water marks rather than being dropped.
- **L-008 — A single user preference is state, not an "always" rule.** Record placement/config choices as *current state* with their decision source, not as `always`/`never` laws; ask before reversing a user-set arrangement. Reserve firm lessons for technically-derivable facts.
- **L-010 — Keep device-backend imports at device entry points; check a dlopen'd native lib by importing its binding.** PortAudio probes host audio controls during `sounddevice` import; eager app-module import can hang model-only evaluators on an unhealthy device. `run_session` + `--list-devices` own the imports; offline replay/test stays hardware-independent. This container's `ld.so.cache` is empty yet libs resolve fine; verify mic prerequisites with `uv run python -c "import sounddevice"` or `dpkg -l libportaudio2`, not `ldconfig -p`.
- **L-016 — Deny-listed paths block tool arguments, not a script's runtime `open()`.** Claude's project deny-list refuses matching Read/Edit/Bash targets; a committed project script that constructs the path internally can still consume the data. Use the existing manifests/tooling for deny-listed corpora rather than exposing bulk inputs directly.
- **L-017 — Corpus evidence = pinned payloads → canonical PCM → content-addressed index.** Dataset Viewer `/rows` lacks a revision selector and can disappear; acquire revision-addressed files directly, verify size + SHA-256 on fresh/cached paths, parse the declared schema, then stage every decoded row before installing an index-addressed cache directory and committing its compact fingerprint last. Pin transient decoders + the expected whole-index hash: package drift becomes an explicit requalification, not silent evidence churn. M10.2 applies this to complete Common Voice Parquet + FLEURS TSV/tar; the ignored JSONL carries row identity/reference/duration/PCM hash, while git carries provenance/distributions/attribution. Count repeated references/audio; uniqueness is a result, not an assumption.
- **L-018 — Maintenance-pass recipe.** Inventory `uv tree --outdated --depth 1` → CVE scan `uv export --format requirements-txt --all-groups --no-emit-project >/tmp/reqs.txt && uvx pip-audit -r /tmp/reqs.txt` (pip-audit scans its own env — feed it the export) → apply lock-only bumps (`uv lock --upgrade-package NAME`) unless the older declared floor is unsupported/security-blocked, in which case raise it deliberately → full gate (import, pytest, ruff, `uvx pyright@1.1.410`) → re-verify the codex leg (not in pytest) via a synthetic `CodexTranslator` turn (`start()` warm-up + `_translate`). Keep package versions out of memory (drift risk).
- **L-019 — A refactor pass on mature, guarded code may correctly yield almost nothing.** Screen each candidate against L-001 ("name the failure mode prevented"); land only those with a nameable win or house-style fix, record the rejected ones in `roadmap.md` so they aren't re-litigated. "Mature; minimal change" is an honest result — don't manufacture edits (pink-elephant pull).
- **L-020 — Roadmap-generation via workflow: the adversarial screen is the deliverable, not the ideation.** Force every finder to read the real code/memory first (ungrounded agents propose out-of-scope textbook features); gate each candidate through a reviewer carrying the project's own laws; record rejects; report a small high-conviction list; verify the highest-stakes survivors against live code yourself and write units by symbol/behavior (line refs drift).
- **L-021 — `CLAUDE.md`'s "For humans: hyphens over other dashes" / de-LLM-smell rule applies to human-facing surfaces only.** Edit only `README.md` and the user-facing CLI strings in `live_stt.py`; leave `.agent/*`, `roadmap.md`, `CLAUDE.md`, code comments, and Claude workflow files (em-dashes deliberate there). Confirm with `grep -nP '[\x{2013}\x{2014}]' README.md`; keep any literal duplicated across code and README in sync.
- **L-022 — Adversarial-review follow-through: fix with a non-vacuous lock, and record the rejects.** Codex Finding 1 (HIGH) surfaced an "enable-over-corpse" startup race (a warm-up/health check that completes just before an async child dies can flip you "live" over a finished reader). Durable pattern: **validate liveness at the commit point** (re-check `_reader_task.done()`/`returncode` immediately before `enabled=True`), not only at spawn. Two reusable test techniques: (a) **deterministic async-EOF** — buffer every response line AND `feed_eof()` in one synchronous burst before the read loop drains; `StreamReader.readline()` returns without yielding when a line is already buffered, so EOF is guaranteed processed before the code under test reads liveness. Answer control requests reactively through `_read_loop` (`_await_pending(rid)` → feed the result line) rather than reaching past it with `set_result` — exercises the real dispatch path. (b) **Prove non-vacuity** — neutralize the fix (`if False and …`), watch the new test fail with the exact bug, restore. **A scripted neutralization matrix must drop bytecode between mutants** (`-B` + `PYTHONDONTWRITEBYTECODE=1` + delete `__pycache__`): CPython invalidates on (size, mtime-to-the-second), so two mutants a second apart that change a module by the same byte count silently reuse the earlier `.pyc` — M13.1's first matrix reported three mutants' red sets as copies of one, which would have certified untested predicates. Tells: identical red lists across unrelated mutants, and a red set that contradicts reading the code. Always print a baseline and a post-restore run, and re-derive any surprising row by hand. Record rejected findings with the reason so they are not re-litigated: Finding 2 (the EOF *cleanup* logs once; a rare second ERROR is `_translate`'s 3-strike branch — distinct, correct, already commented) and Finding 4 (`close()` runs only after `translator_task` ends, so no `_turn` is mid-collect — the no-sentinel claim is correctly scoped) were both rejected as code changes.

- **L-023 — Long continuous speech defeats soft caps and offline decoders; test with a genuinely-continuous stressor.** sherpa's silero `max_speech_duration` (default 20 s) raises the threshold (0.5→0.9, min_silence→0.1 s) instead of hard-cutting — dip-less speech grows unboundedly, so VAD tuning alone cannot bound segment length. Offline attention/transducer models delete content wholesale past ~15–20 s; segment LENGTH, not synthetic-vs-real audio, is the degradation axis (D-010's "TTS collapse" was this), engine-dependent — k2v2 collapses ~3–4× harder than parakeet before mitigation. Build a continuous stressor from real short clips via silero-trimmed speech extents + ~10 ms equal-power crossfade joins (gap-concat leaves clip-edge quiet the VAD rightly splits on); the trim costs onset deletions on isolated decode (silero opens late; 0.4 s pre-pad recovers) → record a per-component baseline and report EXCESS deletion (stressor D − Σ baseline D), else the stressor measures its own construction artifact. Measured construction/QC numbers + WAV sha256 live in `tests/stressor_clips.json`; current shipped-pipeline scores live in `tests/cer_baseline.json`. Prove the corpus honestly, not by loose proxy (`n_seg < n_comp` is gameable — passes at 14/15): continuity = every crossfade-join offset sits inside a cap-OFF VAD segment; soft-cap causality = cap-ON yields more segments than the cap-OFF control. Fix lesson (M9.4): lowering the soft cap 5–12 s still leaves 9–16 s blocks and adds harmful reset boundaries; retain 20 s endpointing, preserve ≤10 s input by identity, then split only longer decode slices into balanced ~2 s low-RMS views with small overlap + conservative exact text merge. Gate total CER alongside deletion so overlap duplication cannot game the deletion target. Genuine narration answers a different question: M9.6's 4:48 chapter naturally endpoints to a ≤9.686 s resliced upper bound, validating long-session completeness but not the >10 s split — keep the continuous stressor as the split-path gate. The committed pause-free gate is 44.7 s; do not claim arbitrary duration because one VAD segment surviving beyond `RING_SECONDS`=60 loses its unretained head. Gotcha: `max_speech_duration` × 16 kHz is an int32 sample count — a huge sentinel (≥~1e6 s) overflows → spurious splits; the control 'off' is a cap just above audio length (`make_vad(max_speech_s=120)`).

- **L-026 — A model bench is only evidence if the harness mirrors production failure handling and the judge sees raw candidates.** Import the real config/instructions/thread options rather than retyping them, and copy the production cleanup path: a `codex app-server` turn that times out keeps running server-side, so without `turn/interrupt` + note drain one stall silently converts every later turn into a timeout — a 5-turn "model failure" that is really one stall plus a harness defect. Present judge candidates between explicit `[Cn]`/`[/Cn]` markers, never through `repr()`/quotes: quoting every candidate makes each look like it added quotes and caps the format-contract score for the whole field at once. Interleave repetitions across configs (rep1 all configs, then rep2) so server-load drift hits every config alike, run configs sequentially so latency stays uncontended, and compare tiny quality gaps paired on the same (item, rep, judge) grading with a bootstrap CI — marginal means put a config "ahead" at differences a paired CI shows as zero. **`turn/interrupt` + note drain is not enough when a turn stalls rather than errors:** M13.1 measured a stall converting a later CONTROL into a 30 s timeout on a shared thread, and the same input on a FRESH thread per turn came back in 3.4 s. Open a thread per measured turn and put a real-input CANARY after every risky one — a row is credible only if the canary behind it is healthy, so carry `canary_s` in the matrix and restart the server whenever it is not.

- **L-027 — A deterministic content probe measures your regex until you read the misses.** Per-item `must`/`forbid` regexes catch real content loss cheaply and objectively, but nearly every early miss was the pattern, not the model: spelled-out numbers ("six units"), hyphens ("stage-two", "12-unit"), synonyms ("decreased" vs "reduced wall motion"), analyte variants ("PaCO2" vs "pCO2"), reversed negation order ("resuscitation will not be performed" against a pattern demanding `not` before `resuscitat`), and legitimate alternate renderings (the Japanese brand "Predonine"). Two habits make the layer trustworthy: (a) validate every pattern against an authored reference translation at corpus-build time and fail the build on mismatch — this catches inverted/typo'd patterns before any turn is spent; (b) treat each first-run miss as a suspect regex and read the actual output before recording it as a model error. Five loosening rounds took 702 turns from ~20 apparent content failures to 7 real ones. Keep every loosening synonym-only, so a wrong dose, side or negation still fails. Mirror trap, and the more dangerous one: a *passing* pattern can hide a real defect. `must.drug` = `prednis|predonine` passes for prednisolone AND prednisone — different molecules — so the declared probe and the aggregate quality scores both scored the wrong-drug turn as clean; only an explicit discriminating check found it. Once a defect is named, write a check that separates it from the correct output instead of reusing the declared pattern, and A/B against that check rather than against the aggregate. Corollary from the instruction probe: attribute a fix to the line that causes it — run one arm per candidate line cumulatively, since the drug-only arm showed the drug line does nothing for gender.
- **L-024 — Backpressure capacity is time; prove it with paced production replay.** Callback block sizes are backend-selected, so a block-count queue cannot express audio headroom; bound queued PCM seconds directly. Fast-as-possible file replay also cannot expose real-time serialization: pace production arrivals on a virtual sample clock, replace only decode cost, and retain the production worker/VAD/ring/queue/drop policy. Keep feeding separate from sequential decode, copy ring slices before queueing them, bound both stages, and failure-couple siblings; otherwise a slow decode either blocks VAD ingestion, lets later ring writes corrupt queued views, or strands a stage after its peer dies. Pair the deterministic stress with live meter/soak checks: modeled timing proves the known workload, not arbitrary host scheduling.

- **L-025 — Evaluator completeness is input/event accounting, not nonempty text.** On the complete short corpus, both offline controls consumed every sample + EOF exactly once yet shared 10 identical empty hypotheses with `segments=[]` (quiet/short material rejected by the common production VAD). These are completed ASR misses → retain the case IDs and score D=N. A failed/partial corpus run means missing/duplicate/reordered IDs, unconsumed audio, wrong EOF/finalization, or a worker exception; it never means one completed clip emitted no text. Keep “nonempty run” corpus-level, or a shared frontend can make every downstream candidate fail by construction. Backend-declared generation/context truncation is a third state: the input run completed, but the output is knowingly terminal-limited → capture native diagnostics per phase/case and fail a separate deterministic content gate instead of relabeling completion or silently scoring the warning away. Publish only exact indexed runs; detailed hashes + aggregate atomicity prevent partial evidence from masquerading as a model result.

- **L-028 — A parallel-corpus reference is a judge-validity probe, never a translation ceiling.** FLEURS EN and JA are independent renderings of a shared source, so neither is a translation of the other and the JA routinely carries specificity the EN drops (`胡氏` → "He"). Scored blind against the JA source, the human EN reached adequacy 4.255/5 while MT over the *perfect* JA transcript reached 4.880 — report that gap as a property of the corpus, never as "MT beats human." Two durable consequences. (a) The low human score is the payoff, not a defect: a judge that docks fluent, human-authored English for diverging from the source is demonstrably grading content rather than rewarding fluency, which is exactly the assurance an adequacy claim needs — so keep the reference in the blind field and read it as instrumentation. (b) String metrics against such a reference are bounded far below their nominal maximum for correct output (oracle chrF2++ 57.75), so use them to rank arms sharing one reference and never as an absolute quality level. Generalize: when a "gold" candidate scores near the system under test, suspect the gold's provenance before crediting the system.

- **L-029 — A seeded report skeleton only checkpoints work when each row is independently answerable.** Two teammates got the identical treatment — a committed skeleton, every cell `unknown`, "flush every 4 rows", and `grep -c unknown` polling. The surface-map agent delivered 17/17 and flushed steadily; the evidence-digest agent delivered 0/12 and ignored three escalating flush directives, ending at 72 % of its window with everything still in its transcript. The difference was row shape, not discipline: map rows were **lookups** (one named surface → its anchor, its test, its gap), each answerable the moment that file was read, so flushing cost nothing. The digest's rows were **synthesis** (build a claim→producer table across ~12 scripts and ~30 result files), where no single row is honestly fillable until nearly everything is read — so the agent rationally kept reading, and the checkpoint contract silently became all-or-nothing. Design consequence: when scoping a teammate, ask whether row *k* can be answered without row *k+1*. If not, restructure the deliverable into per-source rows ("what does `X.py` produce") and make the synthesis its own final row, so the expensive reading is banked as it happens. Recovery when it fails anyway: a live agent's transcript is readable (`context-gauge -p <name>` → `jq` the `tool_use` inputs), so mine it before `TaskStop` — the tool-call record showed which files were read and what was computed, and that salvaged the inventory that never reached disk.

## Smoke checklist — agent-covered vs user-only (L-004)

**Agent-covered (M9):** the two-engine replay/CER gates own short-transcript stability, genuinely-continuous >10 s decode behavior, and the full-file 4:48 narration path. Paced production replay owns the 44.722 s / 20 ms callback / decode-RTF 0.20 backpressure case (max audio queue 0.020/2.000 s, segment queue 1/8, `drop=0`) plus all 7 short clips. **M11.4 extends it to the shipped VAC branch** on real NPU per-update cost, 20 ms callbacks, both pause-free clips: `drop=0`, `forced_trims=0`, segment queue 0 (VAC owns none), audio queue peak 0.760 s (44.722 s stressor) / 1.060 s (182.482 s retention) of the 2.000 s headroom, longest contiguous decode 0.764 s / 1.006 s — and contiguous == max single decode, so one update fires per drain and updates never bunch. Duty 0.544 / 0.642. Margin: the same replays drop at ×1.5 (retention) and ×2.0 (stressor) decode cost, so the shipped path holds real time with roughly a 1.25-1.75× decode-speed reserve, not an open-ended one. **M11.5 adds the shipped path's first agent-rerunnable ACCURACY gate** — `eval_retention.py`, 182 s pause-free, CER 0.0583 on NPU (D-016(e)); every other CER number in tree is still sherpa-only. Pure tests own drain-on-shutdown, sentinel landing, stage-failure cancellation, and translator degradation. These gates exercise the real worker but not a microphone driver, OS signal timing, real Codex happy path, or elapsed multi-hour behavior.

**User-only boundary:** mic capture, device select, latency feel, real Ctrl+C flush, `-o` persistence, Codex cadence, and multi-hour soak. This is the fixed procedure a "Did not verify (L-004)" disclaimer points at; each item names the `live_stt.py` observable that decides pass/fail. **Setup:** models downloaded; `codex` installed on the `PATH` of the machine/environment running live-stt; `codex login` there once for the EN leg (without it: `Translation: unavailable — JA-only`, EN checks N/A). One utterance = speech + a ≥0.5 s pause (`VAD_MIN_SILENCE_S`).

**Live-mic pass (~5 min):**
1. **Devices** — `uv run live-stt --list-devices` lists the `sd.query_devices()` table and exits. Pass: your mic shows with input channels.
2. **Capture + backlog** — `uv run live-stt`, speak. Pass: `JA n:` lines print (capture + decode live); `q=` / `seg=` are absent or brief and clear after each utterance; any `drop=N` fails.
3. **Device select** — `uv run live-stt --device N`. Pass: prints `Mic: #N <name> @ <rate> Hz`; capture works as in (2).
4. **Latency + endpointing (VAC cadence, D-016 — NOT the old 0.6 s VAD-segment rule)** — one sentence, then stop. Pass: partial text grows on the meter status line *while you are still speaking* (first characters ~2.1–2.5 s in on measured audio, committed only where two consecutive decodes agree), then the numbered `JA n:` line lands after you stop; a brief mid-sentence pause does not split it. Committed characters must never be rewritten or duplicated once shown (`emitted` is append-only). On `--engine k2v2|parakeet` the old rule still applies: no partials, `JA n:` ~0.6 s after you stop (0.5 s `VAD_MIN_SILENCE_S` + ~0.1 s decode, D-010).
5. **Translation cadence** — Codex up. Pass: each `EN n:` trails its `JA n:` by ~1 s, shared `n` keeps pairs matched; `--no-translate` suppresses every EN line.
6. **Ctrl+C mid-utterance** — start speaking, Ctrl+C while still talking. Pass: the in-progress `JA n:` still prints (worker flushes the VAD in `finally`), its `EN n:` still lands if Codex is up (translator drains last), then `Stopped.` with no hang (non-blocking shutdown sentinel, T8.1).
7. **Ctrl+C mid-decode** — run `uv run live-stt --engine parakeet`, speak continuously for >20 s, pause, then press Ctrl+C immediately while the slower long-block decode is running. Pass: that block's `JA n:` still lands, its `EN n:` follows if Codex is up, then `Stopped.` with no hang; the VAD feeder and sequential decoder both drain before translation shutdown (M9.5).
8. **Transcript persistence** — `uv run live-stt` (no flags), speak, Ctrl+C. Pass: startup prints `Transcript: <repo>/transcripts/<start-time>.txt`; that file holds `[<ISO-8601>] JA n: …` / `EN n: …` lines, one per event, flushed immediately, closed in `finally`. Then `-o /tmp/stt.txt` → same lines appended there, nothing new in `transcripts/`; `--no-save` → prints `Transcript: not saved (--no-save)` and writes no file; a start-then-immediate-Ctrl+C with no speech leaves no new file (lazy creation).

**Soak (1–3 h)** — watch at start and end:
- **Backlog/drops** — meter `q=`/`seg=`/`drop=`/`tdrop=` stay absent (`q=` / `seg=` may blip and clear). A standing `q=Ns` means PCM awaits VAD within `AUDIO_HEADROOM_S`=2 s; `seg=N` means completed utterances await decode within `SEGMENT_QUEUE_MAX`=8; any `drop=N` means the ingestion pipeline fell behind. `tdrop=N` means translation fell behind (`TRANSLATE_QUEUE_MAX`=50, drop-oldest). **`tskip=N` is a CONTENT decision, never backpressure** — captions declined as repetition loops (M13.1); reading it as backlog corrupts the soak result, and each one costs an EN line but no strike. **Redirected stdout carries no status line, so the same counters ride stderr as HIGH-WATER marks** — `backlog peak: q=… seg=… drop=…`, sampled every `METER_LOG_INTERVAL`=1 s and logged only when a peak moves (a clean run logs nothing), which is what makes `> stt.log` a usable soak record. A peak never clears, so read the LAST such line as the session's worst backlog and its timestamp as when that worst arrived.
- **Thread rotation** — ~every 100 EN turns one `EN` lands a few seconds slower then cadence resumes with no error (codex thread rotation, D-011); EN must keep flowing across the bump.
- **Quota** — out-of-band via `account/rateLimits/read` (not surfaced in-app); expect ≈0 % primary-window movement (D-011). A climbing window → revisit D-011.
- **Memory** (external `ps`/`top`): RSS flat — ring, audio headroom, and segment queue are bounded; `_RESAMPLE_CACHE`≤8; codex `_notes`/`_pending` drain per turn. Steady growth signals a leak.

EN stopping while JA continues is the D-009 JA-only degrade: the 3-consecutive-failure path logs `translation disabled after N…`; a codex EOF in an idle gap logs `codex app-server exited; JA-only…` once and, if a turn is mid-flight, wakes it promptly instead of stalling a window.

- **D-016 — Whisper large-v3-turbo on the NPU under a VAC streaming policy is the default STT path; no prose is ever fed back to the recogniser.** Three measured findings, per-character caption lag, one 4:48 paused narration (N=1383) + M10.5b's 182 s pause-free clip (N=1166). **(a) Policy.** Waiting for silero to close a segment bounds the first character's latency by the last: on pause-free audio silero yields 8 segments of 20–33 s, measuring 15.5 s median / 36.6 s max lag. VAC (silero controlling a LocalAgreement-2 buffer, `streaming.py`) measured 2.5 s / 8.1 s on the same audio and won CER on both corpora and both devices. Pure streaming without the VAD controller *loses* to plain VAD at the median on paused audio (3.18–3.74 s vs 2.43 s) — it bounds the tail, it does not beat pause-triggered emission; VAC is the synthesis. Shipped k2v2+VAD → whisper+VAC on NPU: long_form CER 0.2538→0.2321, retention 0.1587→0.0583 (re-derived M11.5, see (e)) with lag median 14.239→2.483 s. Cost is ~10× decode (RTF 0.041→0.48–0.60), leaving 1.7–2.1× real-time headroom. **(b) Device.** NPU costs nothing in accuracy — unconditioned VAC CER 0.2321/0.0686 vs GPU 0.2292/0.0695 — and forfeits exactly one feature: `libopenvino_genai.so.2026.3.0.0`'s `StaticWhisperPipeline` asserts `'initial_prompt' parameter is not supported on NPU device` and the same for `hotwords`; probed prompt lengths 1/2/4/8/16/32/64/128/200 all raise and 0 passes, so it is a capability gap, not a length budget. `WhisperEngine.set_hotwords` drops the list per device, `--asr-device GPU` unlocks it. User chose the NPU default for efficiency. **(c) Conditioning.** Feeding recent transcript back as prev-text is a landmine: CER 1.8919 on the pause-free clip against 0.1278 unconditioned, 2,126 insertions on 1,166 reference characters, tail repeating one clause 7× — the third reproduction of prompt-induced looping (streaming buffers 0.9328; Kotoba 0.8402). It helps only the paused case (0.2408→0.2054). `CONTEXT_PREV_CHARS` and the carry buffer are deleted. A bounded TERM LIST on the same slot is loop-free and measured 0.2408→0.1873, so terms ride `hotwords`; under the NPU default session context reaches the model through the translator glossary alone. **Honest limits:** the hotwords figures use an ORACLE term list drawn from the reference (an upper bound — passive learning has contributed 0 terms unseeded); long_form absolute CER is inflated by period-vs-modern orthography in the 「ごん狐」 reference, though relative deltas share one reference and normalizer; one clip per corpus; and energy was never measured, because RAPL `energy_uj` is mode 400 `nobody:nogroup` in this container and unreadable even under sudo — NPU-vs-GPU perf/W is a host measurement. **(d) Real-time cost, measured M11.4.** VAC awaits each decode inside the coroutine draining `audio_q`, so unlike the sherpa two-stage worker it does NOT feed VAD during decode — capture buffers into `AUDIO_HEADROOM_S`=2 s instead. That is survivable, not free: per-update NPU decode measured p50 0.552/0.645 s and max 0.764/1.006 s on the two pause-free clips, against a 1 s update cadence, and the trim rule caps the buffer at 11.248 s. The `on_update` seam (`worker`/`_vac_segments`/`replay.py`) is what makes any of this observable; `commit_audio_s` is otherwise discarded at `live_stt.py`'s `commit, _ = await …`. Aggregate RTF is the wrong instrument here — it shows mean compute below real time and says nothing about maximum blockage, which is what the headroom is spent against. Rerun cost varies ~20 % run to run (max decode 0.949→0.764 s across two builds), so the committed trace is one sample and `SCALE_LADDER` is the margin around it. A defect found by `tests/test_streaming.py`: `emitted` shrank when a hypothesis retracted, so the next decode re-committed on-screen characters; holding it append-only removed every insertion on retention (I 12→0, CER 0.0686→0.0583). **(e) Retention CER re-derived, M11.5 — 0.0583 stands, exactly.** The headline number had no producing artifact (only planning reports repeated it), so `tests/eval_retention.py` now re-derives it from committed inputs: hash-check the pinned probe WAV against `retention_probe.json`, replay it through the shipped VAC path, score the concatenated commits against `probe.ja_ref` with `cer.py`. Measured **CER 0.0583** (S=33, D=35, **I=0**, N=1166, hyp 1131 chars) — the headline figure and the append-only fix's I=0 both reproduce to four decimals, so nothing here is superseded. **Re-running the script TODAY returns 0.0609, and that is not a regression:** M13.2 ships `ASR_REPETITION_PENALTY`=1.2, which costs 3 substitutions in 1166 chars (S=33→36, D=35, I=0). 0.0583 is the penalty-free number and reproduces by patching the penalty out. Same run: 8 VAD utterances over the 182.482 s clip, decode 111.9 s ⇒ **RTF 0.613**, marginally above the 0.48-0.60 recorded in (a) and inside M11.4's measured ~20 % run-to-run decode variance ⇒ read that band as **0.48-0.61**, headroom 1.6-2.1×. Placement is an **exact-target inference, not a readback**: `openvino_genai.WhisperPipeline` wraps its compiled model without exposing it, so there is no `EXECUTION_DEVICES` to query; what the run establishes is `requested_device="NPU"` + a successful decode, and `check_device` admits exact names only (an `AUTO:` spelling would relocate silently, which is why `ASR_DEVICE` is a bare name). Rerun cost ≈ 4 min warm. **(f) Caption lag re-derived — 2.483 s reproduces at 2.535 s.** The other producerless headline: the lag evaluator was deleted and predated the `on_update` seam. `tests/eval_vac_lag.py` re-derives it from `vac_decode_trace.json` alone — **no model, no accelerator, no audio, <1 s**, so unlike every other `eval_*` a fresh clone can run it. Per-character lag, never per-commit: a commit carries several characters over an audio span and the reader waited longest for its first, so `end` = `commit_audio_s`, `start` = the previous commit's endpoint, `at_i = start + (end-start)(i+0.5)/len(text)`, `lag_i = emit_s - at_i`, with `emit_s` on M11.4's virtual clock `now = max(now, buffer_end_s) + decode_s`. Measured: **retention_probe median 2.535 s / max 8.157 s** (1,135 chars, 8 utterances) and **stress_long median 2.357 s / max 8.098 s** (277 chars, 2 utterances). Against (a)'s 2.483 s / 8.1 s both are +0.05 s (≈2 %), inside the same ~20 % decode-cost variance band as (e)'s RTF, so **2.483 s stands and is not superseded** — quote (a)'s rounded "2.5 s / 8.1 s" when one decimal will do. Two rules the trace's shape forces, both load-bearing: a FINAL update ends at `buffer_end_s`, not its recorded `commit_audio_s`, because `update()` appends `processor.finish()` AFTER `process()` returned that timestamp, so the flushed tail runs past it; and **never derive lag from final updates alone** — that collapses every early in-speech commit into one utterance-close event and re-measures the VAD policy VAC exists to beat (finals-only reads 11.478/11.618 s median, 4.6× inflated). Qualifier: `commit_audio_s` moves BACKWARD on 6 of 157 commits (max 0.452 s, median 0.084 s), which is the decode-to-decode span drift `streaming.py`'s trim-anchor note already documents; those characters are placed at the previous endpoint, which understates their lag by that amount.
