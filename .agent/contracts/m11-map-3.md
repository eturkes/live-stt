### E2 — `tests/eval_backpressure.py` structure: what forces legacy dispatch, how the virtual clock charges decode cost, what asserts the segment queue, and exactly what must change to represent a VAC run. Line-anchored.
- answer: `worker(object(), …)` supplies no `decode_segments`, forcing the legacy branch. Its executor assumes the last argument is one closed segment, charges `round(len(segment) * decode_rtf)` ticks, and returns `clock.after(cost, fn(*args))`; validation requires `0 < max_segment_depth <= SEGMENT_QUEUE_MAX`. VAC therefore needs a recogniser stub exposing `decode_segments`, executor interception of `StreamingProcessor.process` whose cost is selected from the next empirical row by the processor's current buffer duration, production VAC constants/silero, event counters for speech-open/dispatch/update/decode/trace rows/sample+EOF consumption/max contiguous block, and validation that segment depth is exactly zero rather than positive.
- evidence: `tests/eval_backpressure.py:149-159,168,192-193,254-266`; production dispatch is `live_stt.py:1206-1218`, and per-update executor use is `live_stt.py:1124-1133`.

### E4 — `streaming.py` force-trim counter: the exact surface to add (`file:line`, the state it lives on), and what evidence would rule `forced_trims == 0` versus a committed threshold.
- answer: `StreamingProcessor.forced_trims` already counts each lossy hard trim; add cumulative `State.forced_trims = 0` beside `State.dropped`, then in `_vac_segments.update()` add the per-call delta (`after - before`) immediately after `processor.process`, so all utterances and even a later failure remain visible. Any nonzero threshold needs more than the count: commit the discarded-audio amount per event plus reference-scored transcript loss/CER delta, then bind the threshold to both; otherwise a force trim is an unbounded correctness failure and requires redesign.
- evidence: Existing counter and loss semantics: `streaming.py:82,115,151-162`; production state/update insertion points: `live_stt.py:481-489,1124-1133`; acceptance rule: `.agent/roadmap.md:54`.

### E5 — The design-change risk: what measurement result would force decoupling VAC decode from `audio_q` draining, and should that redesign be its own unit rather than a branch inside M11.4?

- evidence: Queue cap/drop: `live_stt.py:39,496-518,536`; blocking VAC drain/update: `live_stt.py:1124-1129,1155,1187-1189`; the explicit user-before-implementation boundary is `.agent/roadmap.md:54`.
