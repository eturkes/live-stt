## Why kernel

The registry is the specification M11.3d implements against and M11.5b populates; a wrong disposition
is never re-checked downstream — M11.6a consumes the registry as the single claim→source surface
(`m11-map-3.md` G2), so a mis-ruled row silently becomes a shipped doc claim.

## Row schema (strict — an unknown key is an error)

| field | type | rule |
|---|---|---|
| `id` | str | `^C[0-9]+$`, unique across the file |
| `claim` | str | verbatim D-016 claim text, non-empty |
| `claim_value` | number \| str \| bool \| list \| object | non-null; the claim as data |
| `metric` | str | non-empty token (`cer`, `lag_median_s`, `rtf`, `reference_chars`, …) |
| `corpus` | str \| null | `long_form` \| `retention` \| null |
| `arm` | str \| null | `vac` \| `vad` \| `stream` \| `vad_prev` \| `vad_hotwords` \| `whole_file` \| null |
| `device` | str \| null | `NPU` \| `GPU` \| `CPU` \| null |
| `disposition` | str | `measured` \| `corrected` \| `narrowed` \| `legacy-retained` \| `absent` |
| `evaluator_key_path` | list[str] \| null | tokens walked against EVIDENCE |
| `replacement` | object \| null | `{claim: str, source: str}` |
| `legacy_source` | object | `{status: "present"\|"absent", path, key, stored_value}` |
| `note` | str \| null | free text; **required non-empty** when `legacy_source.status == "absent"` |

**No row carries a measured value.** A key named `measured_value` (or any key outside the table) is a
structural error, so a claim can never be mistaken for evidence (`m11u3.md` C5).

## Disposition rules — the determinate pass condition

| disposition | `evaluator_key_path` | `replacement` | extra |
|---|---|---|---|
| `measured` | non-empty list | null | path must resolve in EVIDENCE to a non-null value |
| `corrected` | null | both fields non-empty | states the superseded value in `claim`, the new one in `replacement` |
| `narrowed` | null | both fields non-empty | replacement is the defensible weaker claim |
| `legacy-retained` | null | null | `legacy_source.status == "present"` with `path`, `key`, `stored_value` all non-null |
| `absent` | null | null | transitional; **always an error** — M11.5b must clear every one |

`legacy_source.status == "present"` ⇒ `path`, `key`, `stored_value` all non-null.
`legacy_source.status == "absent"` ⇒ `path`, `key`, `stored_value` all null **and** `note` non-empty.

## Validator contract

`tests/validate_d016_claims.py`, importable, three public entry points:

- `load(path) -> dict` — parse; raise on unreadable/malformed JSON.
- `validate_structure(inventory) -> list[str]` — schema, ids, per-disposition required fields. Evidence-free.
- `validate(inventory, evidence) -> list[str]` — `validate_structure` **plus** resolution and omission.

Error strings are stable and id-prefixed (`C13: …`) so a test can assert on the offending row.

CLI: `python tests/validate_d016_claims.py INVENTORY EVIDENCE` → prints one error per line, exits `1`
when any error, `0` when none.

Key-path resolution walks tokens against EVIDENCE: a token indexes a dict key, or a list position when
it is all digits. A missing key, an out-of-range index, a non-indexable node, or a resolved `null` is a
resolution error. The validator **never compares a resolved value to `claim_value`** — it asserts
presence and sourcing, never truth (`m11u3.md` C5).

### Rulings issued this unit (bind for the milestone)

Six contract ambiguities the diff-blind `test` teammate surfaced, each ruled by MAIN and now
enforced. Three exposed real validator defects rather than mere underspecification:

- **`schema_version`** = the integer `1` alone. `bool` is an `int` subclass and `True == 1`, so
  the original equality test accepted `"schema_version": true`. Fixed with an explicit type test.
- **`NaN`/`Infinity`** rejected by `load`. Python's `json.loads` accepts both by default, and a
  non-finite claim value compares unequal to itself forever. Fixed with `parse_constant`.
- **`metric`** must be non-blank *and* whitespace-free, because it names a key in evaluator output.
- Duplicate id plus an independently malformed row emits **both** errors: uniqueness is a
  whole-file invariant.
- Unknown keys are rejected at the top level and inside `replacement`/`legacy_source`. Nothing
  deeper is a declared shape, so `claim_value` may hold arbitrary nested JSON.
- "Non-empty" means non-blank after stripping, for every string field in the schema.

### Limits

- The registry is a **specification**, not evidence: no row carries a measured value, and the
  validator never compares a resolved value to `claim_value`. Correctness of a *disposition* is
  therefore judgment, re-checked by no downstream consumer — that is why the unit is `kernel`.
- `P7` verifies pointer integrity, not claim truth. For `.md`/`.log` sources it checks that the
  cited lines exist and that numeric stored values appear in them; a prose `stored_value` gets
  line-existence checking alone, because a summary sentence is not byte-comparable.
- Three rows stay deliberately `absent`, so the validator is intentionally **not** a `gate.py`
  step. M11.5a adds that step once the baseline exists.
- `C36`'s `stored_value` was corrected during implementation from the derived ratios
  `[11.73, 10.26]` to the four RTF literals `[0.481, 0.041, 0.595, 0.058]`, because
  `legacy_source.stored_value` must be what the artifact stores, not what was computed from it.
