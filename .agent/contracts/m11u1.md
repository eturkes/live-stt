Authoritative for every M11.1 artifact. Roadmap text governs scope; this file states the testable predicates. MAIN rules every divergence.

## Scope boundary

IN: install route for `openvino`/`openvino-genai`; wheel + sdist membership; `pyproject.toml` description/keywords; the 3 pyright errors + `streaming.py` on the pyright arg list; a committed gate runner (absorbs polish P-001); `replay.py` stale-claim correction; `PYTHONPATH`-clearing documented on whisper commands.

OUT (owned elsewhere, do not touch): shipped-surface unit tests (M11.2); VAC evaluator machinery + `pipeline_fingerprint()` repair (M11.3); backpressure/VAC real-time claims incl. `README.md:80` "Capture and VAD feeding continue during decode" (M11.4); the D-016 baseline run (M11.5); README/models-README/smoke realignment beyond install + PYTHONPATH (M11.6); adding a whisper row to `tests/replay_goldens.json` (M11.3); changing `replay.py`'s `--engine` DEFAULT (M11.3 owns the golden matrix, so the default stays `k2v2` and only the CLAIM is corrected).

Standing constraint: **no production behavior change beyond installability.** Every `live_stt.py`/`streaming.py` edit must be provably behavior-identical. Decode output, segmentation, emission order, and CLI surface stay byte-identical.

### P4 — gate runner
- P4.1 One committed script owns the exact step set and file list; `.agent/memory.md` § Gate identity points at it instead of re-specifying prose steps.
- P4.2 Steps, in order, each labelled blocking or non-blocking:
  1. pytest — blocking
  2. `ruff check` repo-wide — blocking
  3. `ruff format --check` on touched `*.py` files only — blocking. Repo-wide is red by design on 9 hand-laid-out files (D-006/L-001), and an explicitly-passed non-`.py` path is parsed as Python, so the file list must be filtered to `*.py`.
  4. pyright over `live_stt.py replay.py cer.py streaming.py` — blocking
  5. pyright over `tests/` — blocking
  6. offline `import live_stt` — blocking
  7. `tests/eval_models.py --aggregate-only` — NON-BLOCKING and labelled, so the M10-carried whole-file fingerprint defect stays visible without masking the rest (polish P-001 acceptance).
- P4.3 Exit code 0 requires every blocking step to pass. A failing non-blocking step never changes the exit code and is reported as such.
- P4.4 `ruff` is invoked in a form that works without `ruff` on `PATH`.
- P4.5 Non-vacuity: one committed test per blocking step seeds a defect of that step's own class and asserts the runner exits nonzero for that step. A test must not recurse into a full project pytest run.
- P4.6 A committed test locks the step inventory (names, order, blocking flags, production file list) so a silently-dropped step fails the suite. This is the defect that made four D-016-era commits report a green gate while pyright was red.
- P4.7 The runner exits 0 on the tree M11.1 ships.

### P5 — replay.py
- P5.1 No surface claims `k2v2` matches the live-stt default.
- P5.2 The module docstring, the usage line, and `--engine` help name `whisper` and describe what it drives (the real VAC path), while stating why the regression default stays `k2v2`.
- P5.3 The determinism claim is scoped to what is actually deterministic (silero + sherpa offline decode on CPU); it does not silently extend to the whisper/NPU path.
- P5.4 `--engine whisper` still runs: `replay.py <wav> --engine whisper` decodes one clip, rc 0.

### P6 — PYTHONPATH
- P6.1 Every committed surface stating a command that touches the whisper engine carries the clearing requirement. Census, not sample: `README.md`, `models/README.md`, `.agent/memory.md` Commands block, `pyproject.toml`, `replay.py`, `.githooks/`, `tests/*.py` docstrings and argparse help.
- P6.2 The recorded reason names the real failure mode: the inherited `PYTHONPATH` points at a HOST OpenVINO build that cannot execute in-container (needs GLIBC 2.43, container has 2.41), so it shadows the correct wheel and surfaces as `ImportError: cannot import name 'AxisSet' from 'openvino._pyopenvino'` rather than a clean missing-module error.
- P6.3 The gate runner's own whisper-touching step, if any, clears `PYTHONPATH` itself rather than relying on the caller.
