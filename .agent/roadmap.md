Canonical plan + status. Pick the lowest-numbered OPEN unit; restate its acceptance criteria before coding. Trajectory: single-file tool, simplicity over completeness — no frameworks, no config, no premature abstraction. Milestone states: UNPLANNED · IN-PROGRESS · IMPLEMENTED · REVIEWED · PARKED (skipped by MODE dispatch; the entry names its re-entry precondition, and meeting it + clearing the marker returns the milestone to the active-milestone scan). Unit states: OPEN · BLOCKED · DONE. Ledger dispositions: DEFERRED · SUPERSEDED · OUT-OF-SCOPE · REJECTED. Context records = `context-gauge` readings (machine tool, `~/.local/bin`), `N% NK/240K`: `main=` = MAIN, which now carries implementation, and `mate=` = peak teammate high-water; a unit closed at the context reserve records that overrun beside `main=` so PLANNING sizes against the real cost. Units carry `tier=kernel|data|docs` from planning; units planned without one default to `kernel`. A REVIEWED milestone keeps one summary here — status, commit range, shipped surface, gauge band, archive pointer — while its unit detail moves to the named `.agent/archive/<record>.md`, outside the attached set and read on demand.
