## Format

PLAN-prescribed: `[%(asctime)s] %(levelname)s %(message)s`.

## Meter coexistence

The level meter writes to stdout continuously via `\r  [###] …`. Today's stderr writes start with `\n` to break out of the meter line, leaving the old meter frozen one line above. A custom `Formatter` will instead prepend `_LINE_CLEAR` (`\r\x1b[2K`) **only when `sys.stderr.isatty()`** — the meter line gets cleared in place, the message replaces it, `\n` terminator advances, the next meter tick re-paints on the new line. When stderr is redirected to a file, no ANSI prefix bleeds into the log.

The `\r\x1b[2K` is technically a stdout-cursor operation, but stdout and stderr share the terminal's cursor when both are TTYs, so emitting it on stderr clears the meter line just fine.

## Thread safety

`audio_callback` runs on PortAudio's thread. Python `logging` uses an internal `RLock` per handler → safe for the line-354 call.

## Out of scope

- File-output handler for the log itself (`-o` already exists for transcripts; users redirect stderr at the shell).
- Migrating the GEMINI_API_KEY preflight `print` (PLAN scope is explicit).
