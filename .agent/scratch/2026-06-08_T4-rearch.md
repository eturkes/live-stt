## Open questions (research pending)

- Engine: kotoba-whisper-family chunked vs sherpa-onnx streaming transducer (frame-sync, native endpointing) vs whisper.cpp. CPU-only 8-core/30 GB.
- **Endpointing/VAD returns**: Gemini's native VAD did segmentation; local pipeline needs engine-native endpointing or silero-vad. PLAN out-of-scope entry revised.
- Codex surface: persistent app-server/proto vs `codex exec` vs SDK vs raw backend endpoint (ToS-gray). Need instruction control = translation-only output, agentic loop off.
- auth.json mechanics in headless Distrobox; whether host-side login is reusable in-container.
- Quota accounting: what counts as 1 message on Pro; sustained-session viability.

## Risks

- CPU RTF too slow for live JA quality (mitigate: distilled/quantized JA models; bench before committing).
- Per-block translation latency >> Gemini's integrated path (~1.2 s TTFT). Mitigate: persistent process, small prompts, possibly batch/debounce.
- Subscription-surface instability (undocumented endpoint churn). Prefer sanctioned CLI surfaces; isolate behind one small adapter.
- Whisper-family phonetic-substitution hallucinations on short utterances (Gemini showed this too on `paused` clip — spot-check per spike).

## Constraint learned this session

Deny-listed paths (`.env*`, `spike/backends/cache/**`, …) are refused via **Bash too**, twice observed. Treat as fully off-limits through every tool; the app itself reads `.env` at runtime (python-dotenv) which is fine. D-008 amended; orientation updated.
