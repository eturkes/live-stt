# Session roadmap

Continue project along the roadmap; run bare. Route a user-supplied task through `/session-prompt`. State arrives attached: @.agent/roadmap.md @.agent/memory.md. An unexpanded path ⇒ `ls .agent/`: stub the missing file (roadmap: goal + first UNPLANNED milestone from available context; memory: empty), read the present one. Run MODE for the active milestone = first awaiting DONE/REVIEWED. Session scope = exactly one MODE run — WORK-UNIT ships one unit — ending at its close. A PARKED milestone re-enters dispatch when its named precondition is met and its marker cleared.

MODE ← active-milestone status (state change ⇒ scoped commit; stable BLOCKED recheck ⇒ read-only close; convention below):
- UNPLANNED (incl. a still-unsplit future milestone) → PLANNING
- IN-PROGRESS (has an OPEN unit) → WORK-UNIT (lowest OPEN unit)
- IN-PROGRESS (OPEN=0; BLOCKED>0) → WORK-UNIT (lowest BLOCKED, gate recheck)
- IMPLEMENTED (all units DONE; review pending) → MILESTONE-REVIEW

Isolation — worktree mechanics per global `CLAUDE.md` `Subagents`; project bindings: one worktree per teammate at `.scratch/worktrees/<name>`, MAIN alone writing the primary tree, gate toolchain-env recipe → memory.
- Worktrees deliver evidence — suites, oracle bytes, matrices, probe results; the primary tree ships. `prod` harvest alone merges content: MAIN reads `git diff --stat main..wt/<name>` then targeted files, spot-checks the contract's invariant surfaces even on a clean validator run → one scoped commit.

Execution map — MAIN implements + rules; teammates prepare MAIN's decisions, absorb bulk reading, attack MAIN's product, and harden every ruling into a mechanical gate.
- Authorship split: judgment-bearing code (kernel/validator/spec/normative surfaces) = MAIN-authored in the primary tree, start to ship; mechanically-gated artifacts (validator-backed corpus/fixtures/goldens/tables) = teammate production. Teammate output enters through exactly three trust shapes: execution-verified (suites/scripts/repros MAIN reruns), attention-directing (maps/flags/findings MAIN validates before action; validation cost = attention), raw material (drafts/digests MAIN edits into shipped form).
- Assurance scales to the unit's declared tier (project `CLAUDE.md`): `kernel` = full wave battery below; `data` = `prod` alone behind one structural validator + live spot-check at close, later defects fix forward; `docs` = `doc` + consistency pass. Default tier = `kernel`. Off-spine improvements + data-tier remediation append `.agent/polish.md` (acceptance check written at deferral); units stay spine work.
- MAIN's window buys: acceptance contract, batch verdicts on prepared decision points, implementation, divergence + finding rulings, decisive-gate reruns, commits, MAIN-retained files. Bulk payloads (failure logs, transcripts, long reports, green runs) route through a teammate digest w/ pointers; digests = browse context.
- MAIN-retained files = `.agent/roadmap.md`, `.agent/memory.md`, `.agent/polish.md`, `.agent/archive/`, `CLAUDE.md`, command/skill files. A teammate drafts a delta into `.scratch/agents/<name>.md`; MAIN reviews it and applies the durable edit.
- Traffic terminates at MAIN: findings, oracle results, digests land in reports MAIN polls; MAIN alone dispatches follow-ups.
- Portfolio (`<role>-m<m>[u<u>][-<k>]`):
  - `map` = code/spec surface map + anchored normative checklist (`file:line` per obligation) + git archaeology (analog units; SHAs = checkable pointers). `res` = bounded question set + explicit WebSearch allowance + the `Authenticated web` route for authenticated/paywalled sources.
  - `spike` = one design alternative validated on real pipeline probes in its worktree; MAIN picks; the decision record enters the contract.
  - `test` = diff-blind (contract + normative docs only). Phase 1 `<NAME>-PREP-<i>`: enumerate edge inputs + divergent contract readings ⇒ MAIN batch-rules expected outcomes — the verdict table becomes probe corpus + contract clarifications. Phase 2 `<NAME>-DONE-<i>`: encode every verdict + own adversarial probes as the red suite MAIN implements against.
  - `orc` = reference implementation of the identical contract in its worktree — differential instrument: divergences vs MAIN = review targets, bytes stay evidence.
  - `prod` = validator-gated artifact production: before dispatch MAIN ships the contract's predicates as an EXECUTABLE validator + commits the seed it grades; the teammate reports once its own output passes. `doc` = drafts from contract + shipped code; MAIN edits into place.
  - `diff` = cross-checks as committed scripts + outputs (credited by MAIN rerun): MAIN impl vs each oracle over the probe corpus (output-hash where deterministic), red suite × every impl.
  - `rev` + `rev2` = adversarial review of MAIN's diff on declared complementary lenses — correctness/spec + claim soundness + guarantee-vs-claim gaps + CLAUDE.md conformance | mutation campaign (mutate touched predicates, expect a committed red per mutant) | determinism sweeps. A claimed defect ships as a red test in the reviewer's worktree, red pre-fix + green post-fix; judgment-only findings ⇒ council rule: ≥2 independent lenses confirm ⇒ accept; unique ⇒ MAIN validates by probe before acting.
  - `triage` = on-demand failure intake: full log → minimal repro + bisection + cause hypothesis; the repro's rerun is its own credential.
  - `audit` = claim replayer (MILESTONE-REVIEW). `scout` = next unit's probe/corpus surface. `gate` = standing gate-strength track (property tests, differential oracles, mutation automation) — each increment moves one MAIN judgment into the gate.
- Brief = role + scope + contract + worktree path + marker `<NAME>-DONE-<i>` + report destination (`.scratch/agents/<name>.md`) + deliverable-unit total + batch size (global `CLAUDE.md` deliverable-first checkpointing) + validator command its output passes + every consumed upstream id/artifact (inlined or pathed; complete pointers = direct resolution) + questions/follow-ups route exclusively to MAIN (`SendMessage` to a peer silently resumes a stopped agent with its write allowlist live) + `read-and-conform-to` set: gates (project format/lint/type-check/test entry points + quality-gate command), oracles (test suite + corpus, benchmark/demo entry points), scope sources (roadmap, memory, project scope + spec docs) ⇒ teammate disagreement becomes a report for MAIN's ruling. Batch independent spawns in one block; dependent spawns form waves.
- Under abundant teammate capacity, fund `scout`, `gate`, post-acceptance fuzz/property campaigns that escalate on a find. Speculation yields provider capacity to the active wave; unit close stays speculation-independent. Each result distills into roadmap/gate at harvest or expires.
- Review contract (every review teammate, every mode; project `CLAUDE.md` review-termination rule): enumerate the check set from contract + normative docs + touched surface first — that set fixes the report's rows = the review's deliverable-unit total — then adjudicate it against MAIN's diff. Enumeration derives a coverage ledger from every acceptance predicate + changed trust boundary + claim class, then folds it into ≤20 COMPOUND risk-ranked rows, each carrying its subchecks; adjudicate every subcheck, and route rules a tool can decide to deterministic/mutation gates rather than review rows. The cap bounds presentation, never coverage — a ledger that cannot fit means the unit is oversized (`memory.md` L-031), so report that and let MAIN split it. Rows enumerated and left unruled are the failure mode this replaces. Report = the filled table: `pass` + what was checked | `fail` + severity + `file:line` + divergence + breached predicate + impact + acceptance check, shipping a red test wherever one expresses it. An all-`pass` table completes the review. Observations outside the contract land in the report's register section, each with evidence pointer + acceptance check ⇒ MAIN appends the well-formed ones to `.agent/polish.md` unruled and the rest expire with the report. One reviewer per mode carries the project-CLAUDE.md-conformance lens — Authoring rules on every touched durable file + Engineering practices on code. MAIN's ruling on a row binds for the milestone; new evidence is what reopens it.
- Roster at `.scratch/agents/roster.md` from first spawn (append via `tee -a … <<'EOF'`), one row per INSTANCE — name | worktree | transcript (`context-gauge -p <name>`; machine tool, `~/.local/bin`) | marker | watcher bg-task id | last gauge | flushed units (n/total) | status | report. Poll every teammate in one loop from it, writing gauge + flushed-unit count on every pass; retire a row's watcher in the same call that stops or supersedes its teammate.
- Hygiene follows the global `CLAUDE.md` `Subagents` protocol (scoping, marker polling, revive/death cadence, report-file confirmation, `TaskStop` at harvest). Project deltas: gauge = `context-gauge <name>`; successor = `<role>-m<m>u<u>-<k+1>` inheriting report + accepted findings + its predecessor's worktree, whose paths its brief names.
- Close order = global `CLAUDE.md` `Subagents`, run at every commit ending a wave; each mode's close bullet below adds only its own deltas, and the roster is the quiescence sweep's row set.
- Verification: MAIN reruns decisive gates and credits evidence tracing permitted real inputs. Campaign artifacts (matrices, kill lists, sweeps) = committed script + output, credited by rerun. Re-derive a teammate artifact before crediting it — a `.scratch/agents/` PASS from a pre-repair copy certifies the OLD state. Compaction-crossing checkpoint claims require source re-derivation before action.
- Context: per the project `CLAUDE.md` policy MAIN checkpoints (roster + state) before each compaction boundary and continues. WORK-UNIT closes its one unit inside one window and records usage at close — MAIN gauges itself at every wave boundary and funds the next wave while the global `CLAUDE.md` reserve holds; at reserve MAIN closes on the contract, routing unadjudicated rows to `.agent/polish.md` and recording the overrun beside `main=` so PLANNING sizes against it.

PLANNING — split scope into milestones as needed; plan the next milestone.
- Read the prior milestone's commit range + recorded gauges (once a milestone closes its per-unit records live in the `.agent/archive/` record the roadmap stub names); for the first planned milestone read the scope-seed commit(s) the roadmap names. Size every unit to fit MAIN's implementation + coordination inside the one-window aim — against the nearest analog's `main=` (MAIN-implemented units) or `impl=` (earlier delegated units ≈ implementation load).
- MAIN confirms each milestone precondition through project pipeline/tooling. Met ⇒ clear standing block + continue. Pending ⇒ record standing block + evidence; changed record ⇒ commit `roadmap (M<m> block): …`; stable record ⇒ read-only close.
- Wave 1 (one block): `map-m<m>` + parallel `res-m<m>-<i>`, one bounded question set each. Wave 2: `plan-m<m>` drafts the unit split from map + research, declaring every unit's `tier=kernel|data|docs` — milestone = MVP spine (shortest unit path to a consumable artifact; off-spine improvements → `.agent/polish.md`) — and tagging kernel/spec-critical units `oracle` (adds `orc` + the full campaign battery) + validator-gated artifact units `prod` (teammate-produced behind validators). Wave 3: `planrev-m<m>` attacks the draft (sizing realism vs recorded actuals, tier assignments — a data artifact under kernel battery = a sizing defect — dependency order, gate coverage, missed scope, parallelizability, CLAUDE.md conformance). MAIN arbitrates + writes the roadmap; planning holds sole sizing authority, so every unit ships as scoped.
- Sequence gate-independent prep first; mark a gated unit BLOCKED until its precondition is met.
- Close per Close order: set the milestone IN-PROGRESS (units enumerated), commit `roadmap (M<m> plan): …`.

WORK-UNIT.
- Read the last completed unit's commit(s), or the planning commit(s) for the milestone's first unit.
- Precondition transition: recheck BLOCKED first. Met ⇒ clear block, set OPEN, continue. Pending ⇒ retain BLOCKED; materially changed evidence ⇒ update + commit `roadmap (M<m>.<u> block): …`; stable evidence ⇒ read-only close. OPEN + pending ⇒ set BLOCKED, record condition/evidence, make the block commit, close.
- Wave 1 (one block): `map-m<m>u<u>`; material design fork (constructor/naming/spec surface) ⇒ `spike-m<m>u<u>-<alt>` per alternative. MAIN picks from spike evidence and writes the acceptance contract — testable predicates + invariant surfaces + gate identity + probe-corpus seed; every downstream artifact decides against it.
- Wave 2 (one block, contract attached): `test-m<m>u<u>`; `orc-m<m>u<u>` on `oracle` units; `prod-m<m>u<u>` for the unit's validator-gated artifacts; `rev-m<m>u<u>` + `rev2-m<m>u<u>` prep (`<NAME>-PREP-<i>`: contract + normative docs → adversarial probe matrix + acceptance checklist).
- MAIN batch-rules the `test` phase-1 table, then implements in the primary tree against the delivered red suite, harvesting each case as it drives it green (a disputed red ⇒ inspect, rule, correct suite or contract); failure logs + intermediate runs route through `triage-m<m>u<u>`.
- Suite green ⇒ `diff-m<m>u<u>` cross-checks; MAIN rules each divergence with authorship knowledge — oracle consensus against MAIN's reading indicts the contract ⇒ correction lands in verdict table + red suite first, code second. MAIN then sends `rev`/`rev2` the design record + diff pointer ⇒ red-test review (`<NAME>-DONE-<i>`); MAIN fixes its own code; each accepted finding closes on its acceptance check under MAIN's rerun. A judgment-dependent fix takes one re-review round scoped to its own row — fix diff vs that acceptance check, verdict `pass` | `fail` + evidence; a second `fail` on one row ⇒ MAIN rules and the ruling enters the contract.
- Close per Close order — the unit completes on contract predicates green under MAIN's rerun + every review row adjudicated: record `main=` (`context-gauge`; carries implementation) + `mate=` (`context-gauge <name>`, high-water, peak across teammates), both `N% NK/240K`, in the roadmap; set the unit DONE and — once all units are DONE — the milestone IMPLEMENTED; commit `<scope> (M<m>.<u>): …`; the session ends at that commit.

MILESTONE-REVIEW.
- Read every commit within the milestone.
- One block: per-unit reviewers (that unit's commits + touched surfaces; correctness/spec; data-tier units at spot-check grade — sample + claim consistency alone), one cross-cutting reviewer (cross-unit integration; project-CLAUDE.md conformance incl. instruction/memory token-efficiency + obsolescence), one `audit-m<m>` claim replayer (re-derives every roadmap/docs claim for the milestone: full gate suite, reproduction result per recorded number, mismatches flagged). Each reviewer opens by enumerating its check set over its declared surface, then reports under the Review contract.
- MAIN validates + dedupes (council rule); MAIN applies accepted judgment-bearing fixes itself; `prod`-artifact batches go to one fix teammate per cohesive batch (locations + acceptance checks). MAIN's decisive-gate + acceptance-check rerun closes each batch; a judgment-dependent fix takes one originating-reviewer re-review round on WORK-UNIT's terms.
- A requirement-changing design reaches the user before any scope-source edit.
- Close per Close order: set the milestone REVIEWED, move its unit detail to a topical `.agent/archive/<record>.md` the roadmap stub names (project `CLAUDE.md` attached-state rule) leaving one roadmap summary — status, commit range, shipped surface, gauge band, archive pointer — and commit `<scope> (M<m> review): …`.

Commit convention — `<scope> (<trace>): <cause> → <fix>` per project `CLAUDE.md`, trace key in parens: unit `(M<m>.<u>)`, block `(M<m> block)` / `(M<m>.<u> block)`, plan `(M<m> plan)`, review `(M<m> review)`. Grep a milestone's history: `git log --grep "(M<m>[. ]"`.
